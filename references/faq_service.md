# FAQ 服务（使用者问答模式，不触发评测）

> 本文件是 SKILL.md 的关联详情文档，仅在用户提出咨询类问题时由 agent 加载。SKILL.md 仅保留一行指针，以节省主文件上下文。

本 skill 除"跑评测"外，还须能回答使用者关于**本评测器自身**的疑问（怎么用 / 报告怎么读 / 结果含义 / 安全边界）。这是与"评测执行"并列的能力，由 `references/USER_GUIDE.md` 提供权威答案基座。

## 触发识别（进入 FAQ 模式，不跑评测）

当用户话术是**咨询类**而非**执行类**时，进入 FAQ 模式，仅答疑、不调用任何评测脚本、不写工作区：

- 询问本评测器是什么 / 能测什么 / 不能测什么；
- 询问怎么触发、怎么指定被测 skill、跑之前要声明什么；
- 询问"会不会改我的 skill / 删文件 / 出网 / 改自己"等安全边界；
- 询问评测产出（机器读的分数文件 / 给审核人看的报告 / 给作者看的报告）区别、该看哪个；
- 询问结果里的代号 / 分数 / 状态词 / 占位符等术语含义；
- 询问结果写到哪、怎么换位置、怎么续跑 / 重跑某阶段；
- **想自己阅读某份文档**（如"把原理文档给我""我想看使用指南""发我链接我自己看"）——进入**文档直达**，见下方专节。

> 若用户话术同时含"先告诉我 X 是什么，再帮我测 Y"，可先答 FAQ 再进入评测执行；但 FAQ 本身不隐含授权执行。

## 文档直达（提供可点击链接，让用户自己阅读）

**何时用**：用户想**自己看文档**（而非听 agent 转述）时使用。典型动因：对话窗口对 Markdown 的
表格 / Mermaid 图渲染效果差，用专用阅读器（Typora、VS Code 等）打开体验更好；或文档较长、用户需边看边检索。

**提供方式**（两条都要给，用户可选其一）：

| 形式 | 说明 |
|---|---|
| **绝对路径** | 供用户复制到 Finder「前往文件夹」(⌘⇧G) 或阅读器的「打开文件」 |
| **`file://` 链接** | 部分界面可直接点击唤起系统默认应用 |

**路径解析规则（可移植性硬约束）**：

- 本文件（及 SKILL.md 索引）内**一律写相对路径**（如 `references/USER_GUIDE.md`），
  **严禁写死绝对路径**——技能目录位置随安装环境变化，写死会失效且会被机器路径检测判为硬编码缺陷。
- 运行时由 agent 解析为绝对路径：`<本技能目录>/references/USER_GUIDE.md`
  （`<本技能目录>` 即 SKILL.md 所在目录，运行时可知）。

**高频直达文档**（相对路径 → 运行时转绝对路径后提供给用户）：

| 用户想了解 | 提供文档（相对路径） | 说明 |
|---|---|---|
| **这套评测体系的设计思路 / 原理** | `references/skill-evaluation-system.md` | 原理讲解：五个评测面、四大深度评测、AI 与程序双线协作、可进化闭环；**含概念图，适合阅读器打开** |
| **怎么使用这个评测技能** | `references/USER_GUIDE.md` | 使用者指南（人话版）：怎么触发、三份产物受众、怎么读结果、常见问题 |
| **范围与安全边界** | `references/scope_contract.md` | 授权模型（范围授权 vs 逐命令授权） |
| **某阶段的详细流程** | `references/stage0_preflight.md` / `stage1_sample.md` / … | 按阶段号选对应文档 |

> **纪律**：提供链接**不执行任何命令**——不给用户"打开"的动作，只给路径/链接由用户自行打开。
> 若用户要求 agent 代为用某应用打开（如"用 Typora 打开"），那属于**运行范围外命令**，
> 须按 `SKILL.md`「授权与范围契约」单独授权（说明做什么 / 读哪些 / 写哪些 / 风险等级）后再执行。

## 回答纪律（防幻觉，硬规则）

1. **唯一权威源**：FAQ 答案一律以 `references/USER_GUIDE.md` 为基座（其 §1 是什么 / §2 怎么跑 / §3 三份产物受众 / §4 项目状态 / §5 目录布局 / §6 怎么看结果 / §11 常见问题 为高频命中区）；
2. **无据不编**：若 USER_GUIDE 无直接答案，再读 `references/config.md` / `SKILL.md` 相关节核对，**不得凭记忆编造数值、阈值或路径**；确无据则如实说"文档未覆盖，建议…"；
3. **角色分流**：问"能不能上架 / 值不值得用" → 指向给审核人看的报告（benchmark_report.md）；问"哪里要改" → 指向给作者看的报告（problem_report.md）；问"程序怎么读" → 指向 scores.json；
4. **FAQ 索引（稳定命中）**：下表为高频问题与答案锚点，agent 应优先按表定位而非自由发挥，确保回答与文档一致：

| 使用者问题（高频） | 答案锚点（references/USER_GUIDE.md） |
|--------------------|--------------------------------------|
| 这是什么、能测 / 不能测什么 | §1.1、§1.2 |
| 怎么让它测我的 skill / 跑之前必须声明什么 | §2（含项目状态头条）、§4 |
| 只想知道差在哪，要跑全套吗 | §1.2 触发表、§8.1 |
| 完整评测一条命令示例 | §2（示例命令） |
| 会不会改我的被测 skill / 删文件 / 出网 | §11 FAQ（范围契约）、`references/scope_contract.md` |
| 它会不会自己改自己 / 记日志 | §11 FAQ、SKILL.md「运行状态策略」 |
| 三份产物区别、该看哪个 | §3 |
| 结果是"不上架/否决"是不是技能废了 | §6.1、§11 FAQ、§4 |
| 报告里 `FTxx_xxx` 代号是什么 | §11 FAQ |
| 报告里 `<skill-name>` 占位符没替换 | §11 FAQ |
| 带技能跑更慢就算退化吗 | §6.2、§11 FAQ |
| 安全分权重为什么是 0 | §6.2、§11 FAQ、config.md「安全维度的双重身份」 |
| 结果写到哪、怎么换位置 | §2.1、§5 |
| 想重跑某阶段 / 中断续跑 | §8.3、§11 FAQ |
| **想了解这套评测体系的设计思路 / 原理**（要链接自己看） | **文档直达**：`references/skill-evaluation-system.md`（运行时转绝对路径 + `file://` 链接） |
| **想知道怎么使用这个评测技能**（要链接自己看） | **文档直达**：`references/USER_GUIDE.md`（运行时转绝对路径 + `file://` 链接） |

## 与评测执行的关系

FAQ 模式是**只读答疑**，不进入「阶段 0 交互闸门」、不消耗 token 执行任务；仅当用户明确转而要求"测一下"时才切换到执行模式，并按 SKILL.md 其余章节流程推进。
