# 技能质量评估器

## Overview

一套系统化的评估框架，用于评估技能质量，评估对象为 **SKILL.md 及技能目录内的全部支撑文件（supporting files）**（`references/`、`templates/`、`scripts/`、`assets/` 及嵌套子技能）。支撑文件为**一等评测对象**，与 SKILL.md 同等接受四大质量子类的检查，而非仅作背景上下文。评估覆盖四大质量子类：格式检查、对外依赖、内容验证、生态适配。每个检查项按严重、警告、提醒三档级别标记问题，最终输出结构化的评测报告（Markdown）到 `{QUALITY_REPORT}`（results 根下 `quality/` 子目录），重点生成问题清单，面向下游技能改进。（安全合规不在 0阶段 范围，由本 skill Stage 4 的 SafeTest（`references/SafeTest/`）负责。）

与 `skill-authoring-guide` 的关系：后者定义编写规范（"怎么写"），本技能解决已有技能的质量评估（"写得好不好"）。两者核心规则一致，可相互参照。不同 Agent 平台（如 opencode、OpenClaw、Claude Code、Hermes）的技能格式可能存在差异，评估时应以目标平台约定的 SKILL.md 编写规范为参照基准。

### 评测范围（与发布范围对齐）

只评测**随发布包分发的内容**。以下**不属评测对象**：

| 类别 | 内容 | 依据 |
|---|---|---|
| 治理区 | 项目治理目录（维护期内容） | 发布配置第 4 条：不随发布包分发 |
| 规范区 | 变更与规格目录 | 同上 |
| 平台机制目录 | 各 Agent 平台的机制目录 | 同上 |
| 平台机制文件 | 平台专属入口文件与配置 | 平台专属，非技能本体 |
| 治理入口 | 仓库根治理入口文件 | 本技能 SKILL.md：治理入口不发布 |

> 表中一律用**语义指代**而不写具体路径：本节随发布包分发，写治理区路径会成为包内空指针。
> 依据 P8 已验证的做法——**指针目标必须与所在文件的分发范围一致**。
| 版本控制与系统垃圾 | `.git/`、`.gitignore`、`.gitattributes`、`.DS_Store` | 非技能内容 |

**判据**：「带运行行为」**且**「随包分发」——两者同时满足才纳入评测。只带行为但不分发的文件（如 `AGENTS.md` 会被 agent 读取执行，但不随包分发）不评测：用户拿不到，评出来他改不了、改了也不生效。**若将来发布策略改为包含它们，本表须同步更新。**

**目录树呈现**：报告中的「目录结构」反映**正式目录内容**（发布内容），不做额外过滤。上表各项本就不属正式目录，故不显示属正常呈现，而非过滤。

## When to Use

- 向仓库提交新 skill 之前进行质量审计
- 对现有 skill 进行同行评审（peer review）
- 发布前或清理阶段审计 skills
- 在进行 skill 优化前获取评测报告，并基于报告进行修改
- 收到问题如"这个 skill 质量如何"、"这个 skill 写得好不好"或"怎么改进这个 skill"

## Do NOT Use For

- 非 skill 评测（如第三方 MCP 工具、任意代码仓库评审）
- 安全合规评测（由 `本 skill（skill-evaluator）` 的 SafeTest 体系负责，本阶段不输出该维度）

## 评估维度（质量评估）

评估问题按下列四大质量子类分类写入报告。**通过的检查项不输出**，仅输出有问题的检查项。每个检查项可对应多个问题，一个问题一行表格描述。

**空小节写"无"（硬规则）**：若某检查类型/子类型下经检查无任何问题，**不输出空表头**，直接在该小节标题下写"无"；「对外依赖」中某类调用为空、「关键问题汇总」某级别为空同样写"无"。模板中的表格仅为**存在问题时**的格式示例。

**两类「空」必须分开呈现（硬规则）**：

| 呈现 | 含义 | 适用 |
|---|---|---|
| `无` | **已检查**且确实无问题 | 客观维度经脚本确认；主观维度经 LLM 裁定确认 |
| `未检查` | **未产出结论**（需 LLM 语义裁定而未裁定） | 主观维度 |

两者**不得混用**：把「未检查」写成「无」，读者会误认为该检查已通过——属静默降级。

配套约束：① 「未检查」**不得进入关键问题汇总**；② 该标记**只能由渲染层呈现，禁止落成数据行**（否则会被汇总逻辑聚合进汇总节）；③ 下游消费方（skill-doctor）遇「未检查」直接跳过，不作为改进项。

级别定义：
- **严重**（红色 `<font color="red">`）：影响技能正常加载或运行的错误
- **警告**（金黄色 `<font color="GoldenRod">`）：影响技能逻辑解读或执行的问题，LLM解读不稳定，或产生执行歧义
- **提醒**（普通字体）：不影响执行逻辑，但能提升编写质量的事项

同一小节的问题列表按 **严重 → 警告 → 提醒** 排序。

> 安全合规原属评测范围，现已移交 `本 skill（skill-evaluator）` 的 SafeTest，本技能不输出该维度（全技能仅此处详述）。
> 其检查项由 SafeTest 补盲项承接：内容合规 → 新增 `content-policy-compliance`；私隐/修改相关 → 扩展 `sensitive-info-leak` / `permission-boundary`。

### 技能摘要

技能摘要不参与评分，仅汇总用于生成报告。

抽取内容分两类，原则：**客观可数指标用脚本提取，禁止 LLM 主观计数；仅判断性内容用 LLM**。

- **客观统计（必须运行 `scripts/extract_stats.py <目标技能根目录>` 提取，输出 JSON）**：
  - name 字符数、description 字符数、正文（frontmatter 除外）字符数
  - 代码围栏闭合状态、代码块语言标签缺失数、损坏的文件链接、死锚点候选、**重复锚点 slug**（`duplicate_anchor_slugs`）
  - **外联格式文件**可解析性（`external_format_files` / `invalid_external_formats`）、嵌入格式块（既有）
  - **脚本语言清单**（`script_files`，按扩展名/文件名分发语言，供「脚本代码评测」多语言检查）
  - **依赖清单闭环**（`missing_requirements_txt` / `undeclared_python_imports` / `missing_package_json` / `undeclared_node_imports`）
  - **模板占位符**（`template_placeholders`）、HTTP 外链登记（`external_http_links`，可选网络探测，默认跳过）
  - 这些数字是「格式检查」字符阈值（name≤64、description≤1024、正文 5,000–20,000、错别字率分母）及下述各项客观检查的唯一事实来源，LLM 不得重新估算。
- **目录结构**：由资源清单（执行步骤 Phase 0）直接列出，不另计数。
- **主观判断（LLM）**：
  - 多模态能力：如图像识别、OCR、语音识别、TTS、文生图等；仅文本交流则写"无"
  - 功能表（对外功能清单 · **唯一权威定义**）：由 LLM 通读被测技能 `SKILL.md`
    （及 `references/` 等支撑文件中**对外交付**声明）后，归纳其**对外交付的、用户/调用方可直接触发并感知收益**的能力清单。
    本定义是「功能任务清单（阶段 0C）」「质量报告功能表（本节）」「用户功能能力表（benchmark_report §4）」的**唯一共同来源**，三方共用同一产生逻辑与守卫，不得各自另立口径。
    - **仅含 L0 技能目标 / L1 子产物**（层级见被测技能 `SKILL.md`「技能目标与产出物层级」）：用户/调用方真实可感知的交付。
    - **排除 L2 过程策略 / 中间产物 / 内部脚手架**（如样本生成、探测脚手架、内部流水线、配置过程、安全边界、请求、核心工作流、约束、边界、内部等）。
    - **排除通用占位式能力**（任何技能都适用、不特指本技能的表述，如"基础请求 / 结构化结果 / 边界输入不崩溃 / 中间产物供复用 / 通用代码 / 通用总结 / 处理边界 / 异常输入而不崩溃 / 产出中间产物 / 正确响应用户 / 返回结构化"）。
    - **不要求**被测技能显式声明用户功能区章节（`## 能力 / ## 用户功能 / ## 功能 / ## 给用户的输出` 或 `<!-- user_function -->` 标记）；该区若存在仅作锚点辅助定位，**非能力存在的必要条件**。无显式声明时，LLM 仍从全文归纳 L0/L1 对外功能。
    - 字段：名称（用户视角）、实现功能、调用前提、使用示例。
    - 守卫清单（内部过程关键词黑名单 / 通用占位反模式 / 用户功能区白名单）见 `scripts/_common.py` 的 `FUNCTION_TABLE_*` 常量（与「能力追溯硬约束」E27 同源），脚本只引用不重复声明。

### 格式检查（质量子类1）

#### Frontmatter 质量

| 检查项 | 检查标准 | 失败标准 |
|--------|---------|---------|
| 必需字段 | `name`、`description` 均存在且非空 | 缺少任一字段。**客观事实**：Phase 0 `extract_stats.py` 已产出 `missing_frontmatter_fields`（缺失字段列表），本报告直接据此判级 |
| 名称格式有效 | 全小写、仅连字符、≤64 字符 | 有大写字母、空格、下划线、过长。**客观事实**：Phase 0 `extract_stats.py` 已产出 `name_format_valid`（bool），本报告直接据此判级 |
| 描述质量 | ≤1024 字符，须含触发场景语义（不要求字面首句/首字符，只要描述中体现"什么时候该用"）；描述中声明的功能均在正文中有对应实现；除"能做什么"外须含"什么时候该触发"的语义 | 描述功能在主体中未定义，或泛泛如 "Do X"；或仅述能力、未述触发场景（触发语义缺失） |
| Frontmatter 语法有效 | 可解析为 YAML，以 `---` 开头（字节 0），以 `\n---\n` 结尾 | BOM/前导空白、YAML 格式错误、缺少闭合 `---`。**客观事实**：Phase 0 `extract_stats.py` 已产出 `frontmatter_valid`（bool，YAML 解析器不可用时跳过不误报），本报告直接据此判级 |
| 同行匹配元数据存在 | `version`、`author`、`license`、`tags`、`related_skills` 均存在 | 缺少其中任何一项 |
| 平台/环境感知 | 在适用时提及所需平台、依赖或环境变量 | 对有需求的 skill 完全不提平台要求 |
| 标签有意义 | ≥3 个标签，全部与 skill 领域相关；语义明确，独立分隔 | ≤2 个标签，或标签如 ["misc", "other"] |
| 关联 skill 可解析 | `related_skills` 中所有条目都对应已存在的 skill（仓库内或用户本地） | 引用了不存在的 skill |
| 版本格式合法 | `version` 为合法 semver（如 `1.2.3`）或简单版本串（提醒级） | 含空格、字母混入版本号、`v1` 风格未统一 |
| 许可证标识合法 | `license` 为合法 SPDX 标识符（如 `MIT`、`Apache-2.0`）或明确私有声明（提醒级） | 填写随意词（如 `yes`、`proprietary` 非标准标识） |
| 扩展元数据合法 | `agent_compatibility`/`model`/`context`/`allowed-tools` 等扩展字段若存在则取值合法（`agent_compatibility` 为已知 agent 列表子集、`model`/`context` 取值合理）（提醒级） | 填写未知 agent、随意或越界取值 |
| 资源链接有效 | frontmatter 中 `icon` 路径在技能目录内真实存在、`homepage`/`repository` 为合法 URL（若填写）（提醒级） | `icon` 失效、`homepage` 非法或不可达 |
| 描述与正文范围对称 | 描述声明的功能正文均有实现（正向）；正文实现的核心功能描述均有体现（反向，防 scope creep） | 正文实现大量描述未覆盖的功能（描述过窄）；或描述承诺正文未实现（描述过宽） |
| Compatibility 长度限制 | 提供 `compatibility` 时非空且长度受控（如 ≤256 字符），仅列已知平台 / agent 子集 | `compatibility` 为空或超长，兼容性说明失真或污染元数据 |
| 目录名与 Name 一致性 | Skill 根目录 basename 与 frontmatter `name` 完全一致（大小写、连字符规则同「名称格式有效」） | 根目录名与 `name` 不符，发布标识、引用路径与审查对象分裂。**客观事实**：Phase 0 `extract_stats.py` 已产出 `name_dir_mismatch`（bool），本报告直接据此判级 |

#### 结构与组织

| 检查项 | 检查标准 | 失败标准 |
|--------|---------|---------|
| 标题章节 | `# <Title>` 作为首个标题，在概念上与 skill 名称匹配 | 缺失或使用泛泛标题 |
| 概述章节 | `## Overview` 存在，包含 1-2 段解释 | 缺少概述 |
| "何时使用"章节 | `## When to Use` 包含触发条件，含 "Don't use for" 反向触发 | 缺失或只有正向触发 |
| 标题层级连续 | 标题形成连贯树（# → ## → ### → ####），无跳级，无深层嵌套（>4 级） | 嵌套标题层级不连续、跳级 |
| 正文内容针对该 skill | 内容超越通用模板 — 包含领域特定知识 | 所有章节都是通用工具指令 |
| 长度适当 | 正文 5,000–20,000 字符为通过（8,000–14,000 最佳；frontmatter 不计入）；2,000–5,000 或 20,000–30,000 记提醒；<2,000 或 >30,000 记警告（与「技能摘要·客观统计」的 5,000–20,000 阈值及「结构组织·渐进式披露」阈值统一，消除多套数字矛盾） | <2,000 或 >30,000 字符（警告）；2,000–5,000 或 20,000–30,000（提醒） |
| 标准章节完整 | 至少包含 Overview、When to Use、Common Pitfalls、Verification Checklist | 缺 1 个标准章节记提醒；缺 ≥2 个标准章节记警告。**客观事实**：Phase 0 `extract_stats.py` 已产出 `missing_sections`（缺失章节列表），本报告直接据此判级 |
| 步骤编号且有序 | 多步流程使用编号列表（1., 2., 3.）且有清晰顺序 | 多步流程用无序列表，或步骤编号跳跃/重复 |
| 标题嵌套为内容细化关系 | 子标题是父标题的内容细化 | 子标题内容不归属于父标题 |
| 覆盖边缘情况 | 至少有一节讨论失败模式、错误条件或异常场景 | 只覆盖正常路径 |
| 有"常见陷阱"章节 | `## Common Pitfalls`，说明出错时的恢复步骤，≥3 个错误及其修复 | 缺失或 ≤2 个陷阱，或只有预防性指导 |
| 有"验证"章节 | `## Verification Checklist`，含可操作的事后检查 | 缺少该章节或内容空洞 |
| 重复同级标题 | 无两个相同同级标题（如两个 `## X`）；标题与所属内容一致（提醒级） | 重复同级标题、标题与内容明显不归属。**客观事实**：Phase 0 `extract_stats.py` 已产出 `duplicate_headings`（重复标题列表），本报告直接据此判级 |
| 渐进式披露 | 正文 >20,000 字符时，深度细节应外置到 `references/`，SKILL.md 仅留核心步骤与链接（提醒级；与"长度适当"互补：那条查阈值，这条给改进方向） | 超长且未做渐进式披露，读者难以快速定位核心步骤 |
| 多文件缺少索引 | 当 `references/` 等子目录含较多资源文件时，须有索引 / 地图（如目录说明、家族契约文档或 `SKILL.md` 中的文件清单）说明各文件用途与进入点，使模型无需一次性扫描全量 | 子目录文件很多却无任何索引说明，模型被迫全量加载才能定位 |

#### 文法和语法

| 检查项 | 检查标准 | 失败标准 |
|--------|---------|---------|
| 错别字 | 错别字率 ≤1‰（每千字符不超过 1 个）且不影响语义理解；>1‰ 但仅轻微不影响语义记提醒，导致语义错误记警告 | 错别字导致语义错误，或错别字率 >1‰ 且影响阅读 |
| 语义一致 | 全文陈述无矛盾，无相反的指令和步骤内容 | 个别表述和整体语义不相容或相反 |
| 陈述句 | description 和正文使用陈述句或祈使句，指令语义明确。**注**：本条仅管"不用疑问/反问句下指令"；祈使语气与被动语态问题归「文法·语言清晰」，两者不重复计 | 用提问、反问句下指令 |
| 第三人称 | description 和正文使用第三人称或省略人称 | 使用第一或第二人称 |
| 代码围栏闭合 | 所有 ` ``` ` 代码围栏成对闭合（Phase 0 `code_fence_balanced` 为真）；**未闭合会破坏整份文档渲染，属严重** | 存在未闭合围栏，开/闭数量不等 |
| 代码块格式完整 | 代码块须有语言标签（Phase 0 `code_blocks_missing_lang` 为 0）；命令类代码块（如 bash）语法须有效（仅限 SKILL.md 内联代码块；`scripts/` 真实脚本见「脚本代码评测」节） | 代码块无语言标签、命令语法损坏 |
| 嵌入格式可解析 | 嵌入的 `json`/`yaml`/`yml`/`toml` 代码块能被对应解析器解析（Phase 0 `invalid_embedded_formats` 为空；json 用标准库校验，yaml/toml 仅在解析器可用时校验否则跳过）。**非法结构化格式下游无法消费，属严重** | 嵌入 JSON/YAML/TOML 解析失败（括号/缩进/键名错误等） |
| 外联格式可解析 | `references/`/`templates/`/`assets/` 及根级 `*.json`/`*.yaml`/`*.toml`/`*.xml` 等格式文件能被对应解析器解析（Phase 0 `invalid_external_formats` 为空；json/xml 用标准库，yaml/toml 仅解析器可用时校验）。**外联 schema 非法同样下游无法消费，属严重** | 外联格式文件解析失败、与内联描述的结构不一致（schema 一致性见「内容验证·格式与描述一致」） |
| 锚点 slug 无碰撞 | 无两个标题生成相同 slug（Phase 0 `duplicate_anchor_slugs` 为空），否则同一 `#锚点` 跳转歧义 | 多个标题 slug 相同导致内部锚点指向不确定（警告级） |
| 格式一致 | 标题风格统一、代码块格式一致、不混用 `**粗体**` 和 `_斜体_` | 全文格式不一致 |
| 无尾随空白或空章节 | 文件整洁，无空白章节 | 空章节体、过多空行 |
| 语言清晰 | 句子简洁，指令使用祈使语气，无歧义代词 | 描述冗长、步骤中使用被动语态 |
| 语言一致性 | 全文语言风格一致；若声明中文受众，避免无解释地混用英文术语（提醒级） | 中英文混排风格混乱、术语无故切换 |

### 对外依赖（质量子类2）

对外依赖分为三类：调用其他 Tools、调用其他 Skills、调用系统命令。每类分显式调用和隐式调用。

- **显式调用**：正文中明确写出调用名称、准确名称、调用条件
- **隐式调用**：正文未指明具体资源，由目标推导得到（属提醒级别问题）

**输出格式（硬规则，防错位）**：三类调用**各用一个 `####` 子小节承载**，小节内直接写结论（有内容则列条目/表格，无则写"无"）：

```
### 对外依赖

#### 调用其他Tools
<内容或"无">

#### 调用其他Skills
<内容或"无">

#### 调用系统命令
<内容或"无">
```

**禁止**再以「调用其他 Tools：xxx」这类**冒号行**形式另写一份——冒号行与 `####` 子小节双写会导致两者内容错位
（出现"列表写在冒号行、子小节却是无"或"系统命令列表跑到 Skills 小节下"）。值只能落在对应的 `#### 子小节`内。

需额外注意：
- 属于"调用系统命令"的，不重复放在"调用其他 Tools"中
- 若某类调用为空，在报告中写"无"
- 高危指令（修改系统/框架数据、执行高风险系统操作、可能导致崩溃）必须标注（脚本内高危指令同样适用；其安全性质由 SafeTest 负责）
- 脚本相关的**调用参数衔接**、**依赖可复现与声明**检查见「脚本代码评测」节（归入对外依赖）
- 环境变量/运行时前置一致性：正文使用的 `$VAR`、外部命令、运行时要求在「前提/When to Use」中有声明；声明了却从不使用亦记提醒（与「内容验证·内联命令/路径可解析」互补——该查"变量是否定义"，此查"定义是否被声明或使用"）
- **外部服务 / MCP / 网络依赖为第四类**（与 Tools/Skills/Commands 并列）：正文中依赖的 MCP server、外部 API/端点、联网能力须在「前提/When to Use」声明；隐式联网/外部调用未声明记提醒。这类依赖在「脚本代码评测」中同样需核对调用参数衔接与文档-代码一致性。

### 内容验证（质量子类3）

> 含 `scripts/` 资源时，脚本专属检查（语法/风格/参数衔接/依赖可复现/错误处理/文档-代码一致性→本子类；死代码→内容冗余；平台兼容→生态适配）统一见「脚本代码评测」节，本报告仍按归入子类分组。

#### 内容正确

| 检查项 | 检查标准 | 失败标准 |
|--------|---------|---------|
| 陈述事实真实 | 提取事实陈述，检查是否违背已知常识 | 存在明显违背事实的陈述 |
| 推理正确 | 正文中基于事实和逻辑的推理结果正确 | 推理结果和前提不一致 |
| 步骤合理 | 任务步骤符合前后工作顺序和因果 | 前步骤依赖后步骤，或步骤顺序颠倒 |
| 不合理约束 | 完成目标必然需要打破约束 | 约束条件和技能完成目标冲突 |
| 违反推理顺序 | 需要用输出结果来反推前置结构 | 违反数据的因果依赖关系 |

#### 内容完整

| 检查项 | 检查标准 | 失败标准 |
|--------|---------|---------|
| 有具体命令 | ≥3 个具体的 CLI 命令、文件路径或 API 调用 | 只有概念描述无具体步骤 |
| 内联命令/路径可解析 | SKILL.md 代码块内引用的脚本/文件路径在技能目录内真实存在（Phase 0 `broken_file_links` 为空）；引用的 `$VAR` 环境变量在正文有定义或声明 | 命令指向不存在的 `scripts/x.py`、路径不可达、引用未定义变量 |
| 内部锚点有效 | 指向本文档标题的 `#锚点` 链接对应真实存在的标题（Phase 0 `dead_anchors` 为空，LLM 复核大小写/中文 slug） | 锚点指向不存在的章节（死锚点） |
| 工具引用精确 | 提及具体工具名（如 `read_file`、`search_files`）并正确使用参数名 | 模糊引用如 "use a tool" |
| 足够自包含 | 无需先读 3 个其他 skill 就能执行 | 大量交叉引用但未内联上下文 |
| 触发条件精确 | When to Use 将此 skill 与相似 skill 区分开 | 触发条件太宽泛 |
| 已用链接文件 | 如有 assets/ 与 scripts/ 等子目录，SKILL.md 中以具体路径引用 | 有支持文件但未说明如何使用 |
| 过度引用 | 关键信息内联，仅深度探索时引用 | 主要步骤需要外联，导致额外加载 |
| 非流程描述 | Skill 读起来像工作流指南而非工具参考 | 缺乏步骤，步骤靠推理 |
| 前提和输入项模糊 | 不清楚步骤的执行前提和输入项                                 | 依赖 LLM 猜测或复杂推理 |
| 示例充分性 | 至少提供 1 个可工作的端到端示例（命令/输入/预期输出）；无示例读者难上手（提醒级） | 全篇概念描述、无具体可运行示例 |
| 单一聚焦 | 技能聚焦一个明确能力，不混入无关子领域；与「生态适配·与同行无重复」互补——那条查与同行重叠，这条查自身过宽（提醒级）。示例：一个"文件处理"技能混入"数据库管理"无关章节即属过宽 | 一个技能试图覆盖多无关领域、职责发散 |
| 格式定义位置适当 | 大型结构化格式（JSON/YAML，`embedded_format_blocks` 中字节数超阈值，如 >2,000 字节）应外联到 `references/`/`templates/`，SKILL.md 仅留最小示例 + 链接（呼应「结构组织·渐进式披露」）；外联格式文件须被正文引用（提醒级） | 大段格式内联导致 SKILL.md 膨胀、或外联格式文件无引用入口 |
| 格式 schema 完备 | 输出/交换结构以可解析 schema 呈现（而非纯文字罗列），字段含类型/必填/示例值；与「缺少输出结构定义/字段定义」互补——那条查"有否定义"，这条查"是否机器可用" | 结构只给文字列表无字段类型/示例、示例值本身非法 |
| 格式与描述一致 | 嵌入/外联格式定义的字段名、类型、必填与 SKILL.md 正文文字描述一致，不矛盾（复用 Phase 0 解析结果比对） | 正文说"必填字段 X"但 schema 未标注、或字段名拼写不一致 |


#### 评测目标与技能范围对齐（scope symmetry）

> 被评技能必有（显式或隐式）**技能目标**——即其对外交付的能力与产出物（权威源为本技能 `SKILL.md`「技能目标与产出物层级」节，或等价的目标声明）。**评测目标**指本次基准所定义、待测的能力清单（如 `benchmark_manifest.json` 的 `skill_capabilities_tested` 及各功能任务）。两者须**双向对齐**：评测不得越出技能实际作用/产出边界（否则结论误导），技能也不应静默产出评测从未覆盖的能力（否则评测不完整）。若本次基准仅含隐式技能目标而无显式评测清单，则退化为「Frontmatter·描述与正文范围对称」承接。

| 检查项 | 检查标准 | 失败标准 |
|--------|---------|---------|
| 评测目标不越界（以技能作用/产出物为界） | 评测目标所列每一项能力，均能在被测技能的作用域与产出物中找到对应实现依据（对照 SKILL.md 能力层级与对外交付物） | 评测目标包含被测技能实际不提供/不产出的能力（评测越界，就无关能力下结论），**属严重** |
| 技能作用/产出物不溢出评测定义 | 被测技能对外声明/实际产出的能力均有评测目标对应覆盖，或明确标注为内部策略（`tier:l2_internal` / `user_facing:false`）而合理排除 | 技能实际提供的能力/产出显著超出评测目标定义范围却未被评估（覆盖缺口），**属警告** |
| 技能目标显式定义 | 被测技能在 `SKILL.md` 中以独立、结构化方式显式声明其目标与产出物层级（如「技能目标与产出物层级」节），作为评测对齐的权威源 | 技能目标仅靠描述/正文隐式散落、无专门目标声明，对齐需 LLM 推断，**属提醒** |

#### 内容冗余

违反为提醒级别

| 检查项 | 检查标准 | 失败标准 |
|--------|---------|---------|
| 事实冗余 | 正文中无重复的事实陈述，或一个概念多处定义 | 重复的事实陈述或定义 |
| 重复结构定义 | 同一套输出结构在多处定义，应该把相同的结构一处定义，使用的地方进行链接引用 | 结构重复定义，甚至相互有歧义 |
| 跨资源重复定义 | SKILL.md 与 `references/`、`templates/` 等重复同一概念或结构定义，应集中一处定义并链接引用 | 跨文件复制大段相同说明、结构定义互不一致 |
| 格式单一定义 | 同一输出/交换格式不在 SKILL.md 内联嵌入与外联文件**同时维护**（避免双源漂移）；优先外联一处并链接引用 | 同一 schema 在正文嵌入块 + 外联文件各存一份且不一致 |
| 跨资源冲突 | SKILL.md 与自身 `references/`/`templates/` 在**事实、规则、步骤、参数**上无矛盾（与「跨资源重复定义」互补——那条查重复，这条查**相反/冲突**） | 正文说"先 A 后 B"、reference 说"先 B 后 A"，或同一参数取值两处矛盾 |
| 模板占位符一致 | `templates/` 中的 `{{X}}`/`{% X %}` 占位符均在技能内有定义或说明（Phase 0 `template_placeholders` 供核对） | 模板含未定义的占位符、或文档未解释占位符取值 |
| 术语/命名一致性 | 同一概念全文使用统一称谓（如 "Agent"/"Skill"/"技能" 不混指一物） | 同一事物多处用不同名称，读者需推断 |
| 变量冗余定义 | 内容相同的变量集中在一个地方定义，其他地方引用。 | 多处声明同一个变量，甚至有多个名称 |
| 事实冲突 | 同一事实的陈述一致，如指向相同目录，但路径表述不一致 | 不一致的事实陈述 |
| 步骤冗余 | 同一步骤或方法无重复叙述 | 重复的步骤陈述 |
| 步骤冲突 | 同一步骤或方法的陈述一致 | 不一致的步骤陈述 |
| 定义常识性知识 | 重复定义常识性事实、步骤、方法、逻辑 | 定义内容为常识，可以省略不影响理解 |
| 无关内容 | 陈述内容必须和完成任务相关，去除不相关内容 | 叙述无关的事实、步骤 |
| 不相关辅助文件 | 辅助关联文件没有使用场合或无关联引用入口 | 存在不使用的辅助文件 |
| 生成无用文件 | 输出文件不是后续步骤使用或不是给使用者阅读 | 输出文档没有用途 |


#### 内容不明确

| 检查项 | 检查标准 | 失败标准 |
|--------|---------|---------|
| 概念未定义 | 概念有明确定义或属于常识 | 概念存在较大歧义 |
| 缺少实现步骤 | 实现目标有明确定义步骤 | 步骤存在歧义 |
| 缺少关联声明 | 补充内容和主内容的关联有显式定义 | 需通过间接推定 |
| 缺少输出结构定义 | 输出内容或文件有完整结构定义 | 完全依赖 LLM 解读 |
| 缺少输出字段定义 | 输出字段的语义和格式明确定义 | 字段语义和格式易歧义 |
| 缺少写入内容和时机定义 | 写入内容和时机有明确定义 | 写入内容和时机未定义 |
| 多语言完整性 | 若声明支持多语言/本地化，各语言部分均完整、无大段缺失（提醒级） | 声明双语却某语言章节残缺 |
| 输出与错误示例对称 | 既给出成功输出样例，也给出典型失败/错误样例与恢复（提醒级） | 仅成功样例、缺错误处理示例 |
| 受众与语言一致 | 声明的受众语言（如中文）与正文实际语言、术语风格一致（提醒级） | 声明中文受众却通篇英文、或术语无故切换 |

### 生态适配（质量子类4）

> 本子类按三个维度子组评估技能在生态中的"位置 / 标识 / 移植"健康度。每个子组下以表格列出检查项（检查项 | 检查标准 | 失败标准），均由 LLM 依标准判级；可移植性子组含客观提取候选（见各检查项说明）。

#### 分类与关联（Placement & Relations）

> 评估技能在技能仓库/生态里的位置与关联是否合理、依赖是否健康。

| 检查项 | 检查标准 | 失败标准 |
|--------|---------|---------|
| 分类放置正确 | skill 位于最合适的现有分类下 | 放在错误分类或使用非标准分类 |
| 关联 skill 有用 | `related_skills` 引用真正互补的 skill | 有相关 skill 却留空，或引用不相关 skill |
| 与同行无重复 | skill 覆盖领域与最接近同行不同 | 覆盖与现有 skill 相同领域未添加新价值 |
| 关联依赖健康 | `related_skills` 引用关系健康：① 无 A↔B 互相引用成环（无仓库上下文时跳过）；② 事实、规则、步骤和定义在**关联 skill（related_skills 指向的外部技能文件）**内容中无冲突。**注**：本项查"外部关联技能间"的关系健康，与「内容冗余·跨资源冲突」（查本技能内 SKILL.md 与自身 references/templates 的文件间矛盾）对象不同、不重复 | 技能相互引用形成循环依赖，或关联 skill 间存在事实/规则/步骤的冲突 |

#### 身份与触发（Identity & Trigger）

> 评估技能自身标识唯一、触发表达准确且与相似技能边界清晰。

| 检查项 | 检查标准 | 失败标准 |
|--------|---------|---------|
| 同名命名唯一 | 仓库/分类内 `name` 无重复（需比对同级技能；Phase 0 登记的同行清单可辅助；无仓库上下文时跳过） | 两个技能 `name` 相同导致加载冲突 |
| 触发不过宽 | 描述（description / When to Use）范围不宽泛于正文叙述的实际功能。**注**：本项聚焦"触发语义边界"精度，与「格式检查·Frontmatter·描述与正文范围对称」中的"描述过宽"互补——那条查 frontmatter description 与正文的纯对称（文档质量），本项查 When to Use + description 的触发适配性（生态触发）；同一技能不重复计两条"描述过宽"，LLM 判级时归其一即可 | 描述说 "Use when working with X" 但正文范围窄很多 |
| 触发边界清晰 | 触发表达与最接近的相似 skill 边界分明，用户/agent 能区分该用哪一个；不与其他技能触发语义混淆重叠 | 触发描述与相似 skill 高度重叠、用户无法判断用哪个 |
| 用户表达缺失 | description 与 When to Use 含用户真实会使用的触发关键词、短语或具体场景，使静态触发表达覆盖充分 | 缺少用户真实表述（关键词 / 触发短语 / 具体场景），仅以功能视角描述，静态触发覆盖不足 |

#### 可移植性（跨机器/跨平台）

> 评估技能换机器/换平台能否照常工作。其中"路径与机器耦合"覆盖**技能全部文件**（含文档与脚本），"解释器声明规范"与"脚本行尾兼容"针对**脚本代码**。均以客观提取候选 + LLM 复核方式判级（候选不自动判级，避免文档举例路径误判）。

| 检查项 | 检查标准 | 失败标准 |
|--------|---------|---------|
| 路径与机器耦合 | 技能**全部文件**（SKILL.md 正文、`references/`、`templates/`、`assets/`、配置文件及 `scripts/` 脚本代码）均不得硬编码**机器相关绝对路径**——即含用户主目录（`/Users/...`、`/home/...`）、Windows 盘符（`C:\...`、`D:\...`）、UNC 共享（`\\host\share`）、硬编码临时目录（`/tmp/`、`/var/tmp/`、`C:\Temp\`）、特定安装位置的 bin/框架（`/usr/local/bin/`、`/opt/homebrew/`、`/Library/Frameworks/`）等固定本机路径前缀；应使用相对路径（相对技能根）或 Agent 约定变量（`$SKILLS_HOME`、`~/.skills/` 等）。**客观事实**：Phase 0 `extract_stats.py` 已扫描全部文本文件（含脚本）产出 `machine_absolute_paths` 候选清单（path/line/match/kind），本报告以此为基础由 LLM 复核（排除文档中举例用途的路径后）判级。判定口径：出现上述机器相关绝对路径即记**警告**；若该路径是技能核心入口/必读依赖且在他机必然失效，则升**严重** | 技能任意文件中出现 `/Users/...`、`/home/...`、`C:\...` 等机器相关绝对路径而未改用相对路径或约定变量（换机器后路径失效、技能可移植性破坏） |
| 解释器声明规范 | 脚本首行 shebang 须用 `env` 形式（`#!/usr/bin/env bash`、`#!/usr/bin/env python3`）而非硬编码解释器路径（`#!/bin/bash`、`#!/usr/bin/python`）；避免裸调平台专有解释器路径（如 `/usr/bin/x`）。**客观事实**：Phase 0 `extract_stats.py` 产出 `script_shebang`（非 env 形式）候选清单，本报告据此由 LLM 复核判级。判定口径：硬编码解释器/shebang 即记**警告** | 脚本 shebang 硬编码解释器路径，或裸调平台专有解释器路径（跨平台声明下失效） |
| 脚本行尾兼容 | 脚本文件不得为 CRLF 行尾（Linux/macOS 下 shebang 后带 `\r` 致解释器找不到）。**客观事实**：Phase 0 `extract_stats.py` 产出 `crlf_scripts` 候选清单，本报告据此由 LLM 复核判级。判定口径：CRLF 行尾即记**警告** | 脚本为 CRLF 行尾（跨 Unix 平台失效） |

### 脚本代码评测（scripts/ 资源）

> 当技能含 `scripts/` 等代码资源时，下列检查项专用于这些**代码文件**，与 SKILL.md 主体的「文法和语法」（只管文档正文与内联代码块格式）区分。所有代码检查在此**集中执行**（一次进入"代码审查"模式），其发现按末列**归入对应的质量子类**写入报告，不另立子类。**多语言分发**：依 Phase 0 `script_files` 的 `lang` 选择检查器——python→`python -m py_compile`、bash/sh/zsh→`bash -n`、node→`node --check`、powershell→`pwsh -NoProfile -Command "parser"`、其他语言用对应静态检查器（如 `shellcheck`、`golangci-lint`）；检查器不可用时标记"未校验"而非跳过报告，避免静默漏检。

| 检查项 | 检查标准 | 失败标准 | 归入子类 |
|---|---|---|---|
| 代码与脚本语法 | `scripts/` 下各语言脚本依 Phase 0 `script_files` 的 `lang` 分发检查器（python→`py_compile`、bash/sh→`bash -n`、node→`node --check`、powershell→语法解析等），语法可编译、shebang 规范。**注**：静态检查仅做 AST/语法校验，**不绑定名字、不执行**；"未定义符号/运行时错误"属动态验证范畴（见下方验证深度与边界）；检查器不可用时标记"未校验" | 脚本语法错误（对应检查器失败）、缺 shebang、或应检语言却无可用检查器 | 格式检查·文法和语法 |
| 代码风格与可维护性 | 缩进一致、命名规范、无大段注释掉的死代码、单文件长度与技能规模匹配 | 混用 tab/space、大量未使用代码、单文件过长 | 格式检查·文法和语法 |
| 调用参数衔接 | 显式调用脚本/工具/API 的参数名与数量须匹配目标接口；SKILL.md→脚本、脚本→外部命令/API 跨资源同样适用 | 参数名拼写错误、必填缺失、传入未知参数 | 对外依赖 |
| 依赖可复现与声明 | import 的第三方库须在 requirements.txt/package.json **声明包名**（宽松口径：仅查"是否声明了包名"，不要求锁版本/精确 `==x.y.z`，避免因版本格式表述引发歧义）；隐式未声明依赖记问题。Phase 0 已做闭环：`missing_requirements_txt`/`undeclared_python_imports`（py）、`missing_package_json`/`undeclared_node_imports`（node）；`undeclared_python_imports` 含标准库启发式扣减，仍可能误报，LLM 复核 | import 的第三方包未在 requirements.txt/package.json 声明（缺清单或未列包名）；不影响运行的老旧/未锁版本不在此判 | 对外依赖 |
| 错误处理与失败模式 | 脚本对可预期异常有处理（try/except 或非零退出码），覆盖异常/边界路径 | 无错误处理、异常直接崩溃、关键失败静默 | 内容验证 |
| 文档-代码一致性 | SKILL.md 对脚本的输入/输出/退出码/行为的描述与脚本实际实现一致 | 描述与实际行为不符、承诺能力未实现 | 内容验证 |
| 死代码与未使用 | 无未使用 import、未调用函数、注释掉的大段旧实现 | unused import、死函数、被注释的旧代码 | 内容冗余 |
| 平台兼容 | 脚本行为与声明 `platforms` 一致（避免未加守护的 os-specific 调用、裸调系统专有命令且无兼容分支）。**注**：脚本中的"机器相关绝对路径"归 `生态适配·可移植性·路径与机器耦合`，"硬编码解释器/shebang"归 `生态适配·可移植性·解释器声明规范`，"CRLF 行尾"归 `生态适配·可移植性·脚本行尾兼容`——三者已在生态适配子分组统一覆盖，本条仅查纯平台专有**语法/分支**（如仅 Windows 分支调 `cmd.exe` 但声明跨平台且无其他分支） | 声明跨平台却含平台专有写法且无兼容分支 | 生态适配 |

> **验证深度与边界**：本技能对被测脚本**只做静态检查，绝不实际运行**——`import script` 或执行脚本会触发被测技能的真实代码（写文件、联网、改环境等副作用），评测器执行被测对象既不可控也不安全。因此三层验证分工如下：
> | 层 | 手段 | 本技能是否做 | 归属 |
> |---|---|---|---|
> | ①语法静态 | `py_compile`/`bash -n`、风格/死代码/平台写法审查 | **做**（无副作用） | 本技能（脚本代码评测） |
> | ②编译/导入 | `import x`、`x.py --help` 验证依赖可装/入口可启动 | 不做（会执行） | SafeTest 动态验证 |
> | ③运行 | 带 IO 跑通验证功能/文档一致性 | 不做（有副作用） | SafeTest 动态验证 |
> 报告中可在"关键问题汇总"**建议**用户在隔离环境对被测 `scripts/` 做②③动态验证（衔接 SafeTest）。
>
> **可选静态增强（不执行、无副作用，可用则启用）**：若环境已装 `pyflakes`/`shellcheck`，可在①层补充静态检出"未定义符号/未使用导入/语法隐患"——仅做静态分析、不执行代码，与"绝不运行"原则不冲突；工具不可用时跳过，不降级报告。
>
> 高危指令标注（修改系统/框架数据、执行高风险操作、可能导致崩溃）见「对外依赖」节，同样适用于脚本；其安全性质由 SafeTest 负责。

### 支撑文件评估（supporting files）

> 前述四子类默认以 SKILL.md 为对象；但技能常含 `references/`、`templates/`、`scripts/`、`assets/` 等子目录下的**支撑文件（supporting files，即随 SKILL.md 打包的参考文档/脚本/素材/模板）**，它们同为**一等评测对象**，与 SKILL.md 同等接受四子类检查（否则脚本语法错误、损坏链接、孤儿文件会被漏掉）。注意区分：本节"支撑文件"指技能包内的随附文件，与「对外依赖」节检查的**运行时外部资源/系统资源**（外部 API、MCP、网络端点等）是两个不同概念。

#### 支撑文件发现

- **构建支撑文件清单**：`支撑文件清单 = SKILL.md 显式引用的文件 ∪ 技能目录下全部文件`（递归扫描；嵌套子技能——子目录内含 `SKILL.md`——各自独立构建清单并按本框架评估）。
- 逐项标注类型（`md` / `py` / `sh` / `其他`）。

#### 按支撑文件类型适配四子类

| 支撑文件类型 | 主要适用检查 | 典型问题 |
|---|---|---|
| `*.md`（references/、templates/、嵌套 SKILL.md） | 文法语法、内容正确/完整/冗余、链接有效性、结构/格式定义是否重复或冲突、**模板占位符**是否定义 | 损坏的内部链接、跨资源重复或冲突、错别字、空章节、未定义占位符 |
| 外联格式文件（`references/*.json`、`templates/*.yaml`、`*.toml`、`*.xml`、`assets/*.csv` 等） | 格式检查·**外联格式可解析**（Phase 0 `invalid_external_formats`）；内容验证·schema 与描述一致；内容冗余·单一定义 | 外联 schema 非法、与内联描述不一致、内联+外联双源漂移 |
| `scripts/*` 各语言（`*.py`/`*.sh`/`*.js`/`*.ts`/`*.ps1`/`*.rb`/`*.go`/`*.sql`/`Makefile`/`Dockerfile` 等） | 集中按「脚本代码评测」节**依 `script_files.lang` 分发检查器**：语法与风格→格式检查，参数衔接/依赖可复现→对外依赖，错误处理/文档-代码一致性→内容验证，死代码→内容冗余，平台兼容→生态适配；高危指令须标注。**脚本内的"机器相关绝对路径""硬编码解释器/shebang""CRLF 行尾"均纳入「生态适配·可移植性」子分组检查**（见该子分组三项） | 语法错误、风格混乱、隐式依赖（依赖清单闭环）、参数衔接失败、关键失败静默、文档与代码不符、死代码、平台不兼容、脚本内机器相关绝对路径、脚本硬编码解释器/CRLF |
| 依赖清单（`requirements.txt`、`package.json`、`pyproject.toml`、`.env.example`） | 对外依赖·依赖可复现与声明（Phase 0 闭环：缺清单/未声明包）；`.env.example` 与正文声明的环境变量对照 | 缺 requirements.txt、import 未声明、`.env.example` 与实际使用变量不一致 |
| 平台/MCP 清单（`skill.json`、`mcp.json`、`manifest`、`*.mcp.json`） | 对外依赖·外部服务/MCP/网络依赖声明；生态适配·分类与代理兼容 | MCP server 未声明、manifest 与 frontmatter 冲突 |
| **运行时外部依赖提取与核对（0B 可用性预检前置，DEP-EXTRACT）** | 从技能上下文（SKILL.md + scripts/ + 配置）提取外部访问点（http(s):// / 连接串 / host:port / MCP/SaaS），作为 0B 可用性预检的输入：①**覆盖度**——上下文出现外部访问点但 `external_deps` 无对应条目 → 提醒「疑似漏提」；②**一致性**——显式声明的 `target` 须真实出现在技能上下文中，否则告警「声明与代码脱节」；③**隐式使用**——脚本/配置中硬编码的端点须被提取标注 `source: implicit`。此检查为提醒级，**不否决**（属样本准备范畴，非技能缺陷），但须报告显式列出，避免静默 skip | 漏提依赖被可用性探测忽略、AI 声明与代码不一致、隐式端点未标注 |
| 模板文件（`templates/*.md` 含 `{{X}}`） | 内容冗余·模板占位符一致；内容完整·示例充分 | 未定义占位符、模板无使用示例 |
| `assets/`（图片/数据/其他） | 内容冗余 · 不相关辅助文件；外联格式（见上） | 未被任何文件引用的孤儿文件 |
| 根 `README.md` / `LICENSE` | 提醒级：存在性与一致性（与 description 范围不冲突） | 声明开源却无 LICENSE、README 与技能范围脱节 |

#### 引用完整性（双向校验）

- **损坏引用**：SKILL.md 或其他支撑文件引用了不存在的路径（含 `SKILL.md` 直接引用的 `references/`、`scripts/`、`assets/` 标准子目录若不存在亦属此列）→ 记「内容验证 · 已用链接文件」问题（问题位置指向引用方文件:行）。
- **孤儿文件**：支撑文件目录中存在、但未被 SKILL.md 或任何支撑文件引用的文件 → 记「内容冗余 · 不相关辅助文件」问题（问题位置指向该孤儿文件）。

#### 定位器

每个问题记录的「问题位置」必须是可定位的 `文件:行号`（如 `scripts/run.py:12`）；SKILL.md 内问题记为 `SKILL.md:行号`。此定位器是下游 problem_report 索源改进的直接依据。

## 执行步骤

> **执行顺序三原则**
> - **逻辑集中**：同主题检查一次做完（客观统计集中、脚本 8 项集中）。
> - **先易后难**：客观机器可验 → 主观 LLM 判断 → 跨资源追踪 → 综合外部对比。
> - **承前启后**：Phase 0 产出的客观事实被后续所有子类复用；后续阶段消费前序阶段结论，避免重复劳动与口径漂移。

> **计划先行（Plan-First）—— 评测计划与断点续评**：评测维度多、覆盖资源广、子任务多、耗时长，须在**执行任何判定之前**先产出一份可持久化的《评测计划》再照单执行：
> - **计划内容**：① 资源范围（被评技能实际含哪些资源文件及类型）；② 维度选型（四大子类全部纳入，但各子类内**仅保留与被测技能相关的检查项**，不相关的以 `[~]` 标注并附理由跳过，减少无效计算）；③ 子任务清单（按执行顺序编号，逐项 `[ ]`）。
> - **产物**：`<skill-name>_eval_plan.md`（Markdown 勾选清单，**独立于评测报告**的工作产物，不受"仅输出报告 / 无 JSON"约束）。
> - **断点续评**：重跑时若该计划已存在，读取后**仅执行仍为 `[ ]` 的条目**、已 `[x]` 的跳过——支持中途中断后从断点继续，且不会遗漏剩余任务。
> - **防遗漏**：所有待办在计划阶段一次性枚举完毕，长流程中无需依赖记忆。
> - **执行日志（自优化）**：异常 / 偏离计划时向 `{EXEC_LOG}` 追加条目，模板与续跑协议 → 见 skill 根 `SKILL.md`「执行纪律」。阶段 0 计划即 `{PF_EVAL_PLAN}`。

0. **建立事实基座（机器可验，全局共享输入）：**
   - 按「支撑文件评估」构建**支撑文件清单**（公式：`SKILL.md 引用文件 ∪ 技能目录下全部文件`，逐项标注类型；嵌套子技能递归独立建清单）。
   - **（计划先行）产出《评测计划》`<skill-name>_eval_plan.md`**：基于支撑文件清单做维度选型——四大子类全部纳入，但各子类内仅保留与被测技能相关的检查项（如技能无 `scripts/` 则「脚本代码评测」整体 `[~]` 跳过；无 `templates/` 则模板占位符检查 `[~]`；无 HTTP 外链则网络探测 `[~]`；无 `references/` 则跨资源重复/冲突检查 `[~]`），逐项列 `[ ]` 子任务并按执行顺序编号。该计划是后续断点续评的依据；重跑时若计划已存在则只读 `[ ]` 项、已 `[x]` 跳过。
   - 运行客观提取：`python3 scripts/extract_stats.py <目标技能根目录>`，得到 name/description/正文 字符数、代码围栏闭合、代码块标签缺失、损坏链接、死锚点候选、**重复锚点 slug**、嵌入/外联格式块可解析性、`script_files` 语言清单、依赖清单闭环、`template_placeholders`、HTTP 外链登记、**机器相关绝对路径候选（`machine_absolute_paths`）、脚本 shebang 候选（`script_shebang`）、CRLF 脚本候选（`crlf_scripts`，覆盖全部文本文件含脚本，供「生态适配·可移植性」复核）**、**结构类客观字段（`name_format_valid`/`frontmatter_valid`/`missing_frontmatter_fields`/`name_dir_mismatch`/`missing_sections`/`duplicate_headings`，供「格式检查·必需字段/名称格式/Frontmatter/目录名一致/标准章节/重复标题」直接判级）**等**确定性事实**（JSON 输出，产物落于 `{PF_STATS}`；后续子类阶段禁止用 LLM 重新计数）。`script_files` 同时用于登记被测技能实际包含的语言，驱动 Phase 3 多语言分发；**提取范围受计划选型约束**（对应资源缺失则跳过相关统计，减少无效计算）。
   - 对 `scripts/` 脚本做语法预检（`python -m py_compile` / `bash -n`）。
   - 列出同行 skill 路径清单（仅登记，供 Phase 5 使用）。

1. **格式检查（先客观后主观）：**
   - 客观部分直接用 Phase 0 事实判阈值：name≤64、description≤1024、正文 5,000–20,000 字符、代码围栏闭合、代码块有语言标签、嵌入格式可解析（`invalid_embedded_formats` 为空）、**外联格式可解析（`invalid_external_formats` 为空）**、**锚点 slug 无碰撞（`duplicate_anchor_slugs` 为空）**、frontmatter 可解析（BOM/前导空白/闭合 `---`）。
   - 主观部分（文法/语义/格式一致/第三人称/错别字率）由 LLM 判；错别字率沿用 Phase 0 的 `body_chars` 作分母。

2. **对外依赖（追踪，承前用 Phase 0 清单与链接解析）：**
   - 遍历 Tools/Skills/Commands 显式/隐式调用，结合 Phase 0 资源清单与损坏链接结果追踪调用链；脚本参数衔接/依赖可复现见专节（Phase 3 回填）。

3. **脚本代码评测（集中，产出回填 1/2/4/5）：**
   - 对 `scripts/` 集中跑 8 项（语法→风格→参数衔接→依赖可复现→错误处理→文档-代码一致性→死代码→平台兼容），按末列归入子类回填至 Phase 1/2/4/5。

4. **内容验证（最难，依赖 Phase 0/2/3 事实）：**
   - 正确性/完整/冗余/歧义；消费 Phase 0 的 `broken_file_links`（内联命令/路径可解析）、`dead_anchors`（内部锚点有效），并将 Phase 2 的断裂依赖、Phase 3 的文档-代码不一致/死代码作为证据。
   - **评测目标与技能范围对齐**：若本次基准已定义显式评测目标清单（manifest `skill_capabilities_tested` / 功能任务），对照被测技能 `SKILL.md`「技能目标与产出物层级」做双向对齐（评测越界→严重、技能溢出评测定义→警告）；仅隐式目标时退化为「Frontmatter·描述与正文范围对称」。

5. **生态适配（需外部上下文，置末）：**
   - **分类与关联**：用 Phase 0 登记的同行清单做对比，结合全部前置发现，判分类放置 / 关联 skill 有用 / 与同行无重复 / 关联依赖健康（无环 + 内容不冲突）。
   - **身份与触发**：判同名命名唯一、触发不过宽（描述不宽于正文）、触发边界清晰（与相似 skill 不混淆）、用户表达缺失。
   - **可移植性**：消费 Phase 0 客观提取候选逐项复核——
     - *路径与机器耦合*：消费 `machine_absolute_paths` 清单，逐条核对被测技能**全部文件**（含脚本）是否硬编码机器相关绝对路径；排除文档中"举例用途"的路径后按"警告/严重"判级；
     - *解释器声明规范*：消费 `script_shebang` 清单，核对脚本 shebang 是否为 `env` 形式；
     - *脚本行尾兼容*：消费 `crlf_scripts` 清单，核对脚本是否 CRLF 行尾。

6. **汇总关键问题**到"关键问题汇总"（不含"提醒"级别事项）。

7. **生成报告**：用 `assets/report.template.md` 模板，保存为 `{QUALITY_REPORT}`（results 根下 `quality/` 子目录）（**无安全合规节、无评分节**）；无问题的小节直接写"无"、不输出空表头（见「评估维度」空小节规则），模板顶部的"模板说明"段生成时删除。

8. **验证输出完整性**：报告含四大质量子类、未生成 `<skill-name>评测.json`、无评分章节（见 Verification Checklist）；并确认 `<skill-name>_eval_plan.md` 中所有 `[ ]` 子任务均已 `[x]` 或合理 `[~]` 跳过，无遗漏待办（断点续评的最终闭环）。**注**：在本 skill 整合流水线中，此计划闭环由 `{PF_VALIDATOR} --plan {PF_EVAL_PLAN}` **机器强制**（残留 `[ ]` 即门禁失败），无需人工守门。

> 各子类阶段通用规则：逐项检查记录证据；问题「问题位置」写成 `文件:行号`（SKILL.md 内记为 `SKILL.md:行号`）；路径引用用 Agent 约定变量（`$SKILLS_HOME`、`~/.skills/` 等）而非硬编码绝对路径；通过的检查项不输出（见评估维度规则），仅记录有问题项；**执行时同步在 `<skill-name>_eval_plan.md` 将对应子任务勾选为 `[x]`（不相关项标 `[~]`），以支持断点续评与防遗漏**。

## 0B 可用性预检（条件步，性能/安全耗时测试之前置闸门）

> **定位**：阶段 0 含两步——0A 静态质量预检（必跑，见上）+ **0B 可用性预检（条件步）**。0B 在 0A 之后、阶段 1 之前执行，是「耗时测试（阶段 1–4 真实跑案例）」的总前置闸门：可用性不过就不该浪费时间跑性能/安全。
> **是否执行（关键）**：0B **不是所有技能都跑**。仅当依赖提取器从被测技能上下文提取到 `external_deps` 非空时才执行；提取为空则 `dependency_skipped=true`，0B **自然跳过**，阶段 0 仅剩 0A。即"无外部依赖的技能不需要可用性评测"。
> **详细规格**：维度族（D1–D6 checker）、裁决矩阵、与 SafeTest 边界、输出常量，见 `references/dependency_availability.md`（本步骤的执行规格权威源）。改探测行为前须先 `read_file` 该规格。

### 0B 执行步骤

1. **依赖提取（DEP-EXTRACT）**：`python3 scripts/extract_deps.py --skill-dir <SOURCE_DIR> --manifest <SAMPLE_DIR>/benchmark_manifest.json --output <SAMPLE_DIR>/dependency_extract.json --write-manifest`。从 SKILL.md + scripts + 配置静态扫描外部访问点，写入 manifest 的 `external_deps`（提取产物承载格式，带 `source: explicit|implicit`）。
2. **判定是否进入探测**：`external_deps` 为空 → 记 `dependency_skipped=true`、报告「未发现外部依赖」，**跳过 3–4**，直接进入阶段 1；非空 → 继续。
3. **可用性探测（DEP-AVAIL）**：`python3 scripts/dep_probe.py --manifest <SAMPLE_DIR>/benchmark_manifest.json --skill-dir <SOURCE_DIR> --output <SAMPLE_DIR>/dependency_probe.json --report-md <SAMPLE_DIR>/dependency_report.md`。逐依赖跑 D1–D6 checker。
4. **并入报告 + 硬拦截**：
   - 将 `dependency_report.md` 章节并入 `{QUALITY_REPORT}`（若 `--stage0` 启用；否则独立留存）。
   - 若探测发现**契约型结构性缺陷（contract_defect）** → 按阶段 0 预检闸门**硬拦截**，`exit 1` 中止后续阶段 1–4（报告已落盘，不无声退出）。
   - 瞬态失败（网络超时/5xx/429）与配置缺失（需用户提供凭据）→ **不否决**，仅报告「瞬态观测 / 未配置」章节并附重试/补配置建议。

### 0B DoD（验证闭环）

- [ ] `external_deps` 为空时 `dependency_skipped=true` 且 0B 跳过、不阻断。
- [ ] 非空时 D1–D6 全部跑过，每个 checker 显式输出 `kind`（structural/transient/config）。
- [ ] contract_defect 触发阶段 0 硬拦截（`exit 1`）；transient/config 不否决。
- [ ] 可用性章节已并入 `{QUALITY_REPORT}` 或独立留存 `dependency_report.md`。

## 输出约定

本技能产出主文件 **`quality_report.md`**（Markdown 评测报告，问题清单优先、无评分），保存到 `{QUALITY_REPORT}`（results 根下 `quality/` 子目录），格式遵循 `assets/report.template.md`。生成与保存步骤见执行步骤 7。0B 可用性章节作为补充节并入同一报告（无外部依赖时该节缺省）。

> **必须向使用者播报报告位置**：评测流程结束（无论门禁通过与否）后，须用一句话把报告实际完整路径（即 `{QUALITY_REPORT}` 经 `SKILL_EVALUATOR_RESULTS_ROOT` 重定向后的真实解析值）告知使用者，例如「质量报告已生成：<真实绝对路径>」。不可仅把报告写到磁盘而不告知路径——使用者默认不知道 results 目录在哪。

## Common Pitfalls

- 如果需要验证的技能找不到，报告文档找不到的报错即可，无需输出报告文档
- 如果 related_skills 找不到，屏幕提示文档找不到，但不影响报告输出
- 确保 Markdown 报告保存到下载目录，而非仅输出到屏幕；保存后必须向使用者播报报告完整路径（见「输出约定」播报规则），不可只落盘不告知
- 评估目标技能时，检查其多步流程的步骤编号连续（无重复如两个"4."）
- Markdown 报告必须包含全部四个质量子类（格式检查、对外依赖、内容验证、生态适配），且**不含量身合规节与评分节**，不可遗漏质量子类

## Verification Checklist

- 检查输出报告格式符合 `assets/report.template.md` 模板要求
- 通过 skill-authoring-guide 或目标平台约定的编写规范补充报告输出内容
- **检查 `quality_report.md` 含四大质量子类、不含安全合规节与评分节**（规则见评估维度与执行步骤 8）
- **检查 `<skill-name>_eval_plan.md` 评测计划存在且所有子任务已 `[x]` 或 `[~]`**（无残留 `[ ]`，规则见执行步骤 Plan-First 与步骤 8）
