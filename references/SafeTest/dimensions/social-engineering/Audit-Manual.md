# 社会工程风险审计手册

## 1. 基本信息

- **版本**：v1.0
- **适用范围**：SpecAgent
- **审计范围**：Skill 描述、文档和元数据
- **核心目标**：识别诱导用户信任或降低警惕性的心理操纵风险

### 1.1 SafeTest 中的定位

- **分类角色**：交叉人类因素视角，非唯一顶层分类
- **主 OWASP 对齐**：`ASI09 人-Agent 信任利用`
- **次要 OWASP 对齐**：`ASI01 Agent 目标劫持`、`ASI10 流氓 Agent`
- **主要用途**：评审信任、权威、紧迫性或可解释性是否被用于降低人类警惕性

---

## 2. 审计指南与定义

### 2.1 审计原则

| 原则 | 说明 |
|------|------|
| **描述与实质分离** | 不信任 Skill 描述，必须依据实际代码行为 |
| **独立性原则** | 不受流行度指标、权威背书等影响 |
| **怀疑精神** | 警惕"完美""官方""推荐"等措辞 |

### 2.2 术语表

| 术语 | 定义 |
|------|------|
| **权威伪装** | 利用知名品牌、名人或组织名称获取信任 |
| **流行度伪造** | 伪造下载量、评分等流行度指标 |
| **紧迫感诱导** | 制造虚假紧迫感迫使用户匆忙决策 |
| **信任转移** | 借助平台或第三方信誉背书 |
| **描述欺诈** | 声称的功能与实际功能严重不匹配 |

---

## 3. 风险类别与评级

| 风险级别 | 定义说明 | 典型场景 |
|---------|---------|---------|
| **P0（致命）** | 冒充官方/权威机构，导致严重信任滥用 | 冒充 Google、OpenAI 官方工具 |
| **P1（严重）** | 使用明显伪造的指标或严重描述欺诈 | 声称"100 万用户"但代码简单、功能与描述不匹配 |
| **P2（轻微）** | 使用营销话术或略夸张的描述 | 使用"最好""最快"绝对化用语 |
| **P3（提示）** | 略偏离最佳实践 | 使用 emoji、过度装饰的描述 |

## 4. 审计检查清单

### 4.1 权威伪装检查
- [ ] **检查点 1**：Skill 名称是否含知名品牌（Google、OpenAI、Microsoft）
- [ ] **检查点 2**：Skill 名称是否含名人姓名（Elon、Musk、Sam Altman）
- [ ] **检查点 3**：是否声称"官方认证""合作伙伴""推荐"
- [ ] **检查点 4**：是否模仿知名产品的界面或交互模式

### 4.2 流行度验证
- [ ] **检查点 5**：是否强调高下载量、评分（如"10000+ 用户"）
- [ ] **检查点 6**：是否展示"五星评级""编辑推荐"徽章
- [ ] **检查点 7**：流行度指标是否可验证（如 GitHub stars 存在）

### 4.3 紧迫感与诱导
- [ ] **检查点 8**：是否使用"限时免费""立即安装"等紧迫性语言
- [ ] **检查点 9**：是否制造稀缺感（"仅剩 X 个名额"）
- [ ] **检查点 10**：是否使用互惠陷阱（先免费后要求权限）

### 4.4 描述与现实对比
- [ ] **检查点 11**：对比 SKILL.md 描述与实际代码功能
- [ ] **检查点 12**：标记夸大或隐藏的功能
- [ ] **检查点 13**：检查是否用"教育""演示"降低警惕性
- [ ] **检查点 14**：验证免责声明是否与风险水平匹配

## 5. 评分标准与公式

### 5.1 评分公式

$$Score = 100 - (N_{P0} \times 35) - (N_{P1} \times 20) - (N_{P2} \times 10) - (N_{P3} \times 5)$$

- $N_{Px}$：对应风险级别的发现数量
- **最低分数**：0 分

### 5.2 通过阈值

| 等级 | 分数要求 | P0 限制 |
|------|---------|---------|
| **优秀** | ≥ 90 分 | $N_{P0} = 0$ |
| **通过** | ≥ 60 分 | $N_{P0} = 0$ |
| **不通过** | < 60 分 | 或 $N_{P0} > 0$ |

### 5.3 加分项

- 描述清晰准确，无夸大：+5 分
- 主动披露限制和风险：+3 分
