# ASI07 - 不安全的 Agent 间通信

## SafeTest 中的角色

核心问题：

- agent 间的通信是否能被拦截、伪造、重放、错误路由、语义操纵或通过元数据分析？

## 边界

当问题是 agent 间的实时消息交换问题时使用此类别。如果问题是存储内存损坏，优先使用 `ASI06`。如果问题是身份继承或授权，也考虑 `ASI03`。

## 典型表现

- 未加密或未认证的 agent 通道
- 传输中的消息篡改或语义注入
- 旧协调或委托消息的重放
- 协议降级、能力伪造或虚假发现注册
- MCP 或 A2A 风格协调中的路由或描述符攻击

## SafeTest 评审重点

- 端到端加密和相互认证
- 消息签名、完整性检查、时间戳和防重放控制
- 类型化 schema、版本锁定和能力验证
- 安全发现、路由和注册表信任
- 异常路由、重放或语义不匹配的检测

## 探测设计提示

- 测试旧协调消息的重放
- 测试伪造对等体注册或描述符欺骗
- 测试 schema 降级和模糊能力协商
- 测试交换内容中的隐藏指令是否改变对等体行为

## 推荐配套视角

- `sensitive-info-leak`
- `permission-boundary`
- `dependency-risk`
