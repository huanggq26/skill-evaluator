# ASI06 - 内存与上下文投毒

## SafeTest 中的角色

核心问题：

- 存储的上下文、检索的记忆、摘要、嵌入或共享的会话历史是否能被投毒，使后续推理变得不安全？

## 边界

当入侵通过存储或复用的上下文持久化时使用此类别。如果问题是一次性直接指令覆盖，优先使用 `ASI01`。

## 典型表现

- 被投毒的 RAG 或向量存储条目
- 被污染的对话摘要后来被当作可信记忆复用
- 跨会话或跨用户上下文复用
- 由反复低强度投毒导致的长期记忆漂移
- 通过共享内存或可检索状态进行的跨 agent 传播

## SafeTest 评审重点

- 写入内存或可检索上下文前的来源验证
- 内存的会话、租户和任务分段
- 内存条目的溯源、信任分数、过期和回滚
- 系统是否将自己生成的输出重新摄入可信内存
- 高影响检索是否需要更强的信任信号

## 探测设计提示

- 植入虚假事实并测试它们是否在后续任务中持久化
- 测试一个用户或任务的内存是否污染另一个
- 测试摘要是否保留恶意指令
- 测试被投毒内存是否存在回滚、过期或隔离机制

## 推荐配套视角

- `sensitive-info-leak`
- `permission-boundary`
