# 敏感信息泄露审计手册

## 1. 基本信息

- **版本**：v1.0
- **适用范围**：SpecAgent
- **审计范围**：Python Skills 中敏感数据的处理、存储和传输
- **核心目标**：识别密钥、密码、个人信息等的泄露风险

### 1.1 SafeTest 中的定位

- **分类角色**：交叉数据暴露视角，非唯一顶层分类
- **主 OWASP 对齐**：`ASI03 身份与权限滥用`、`ASI06 内存与上下文投毒`、`ASI07 不安全的 Agent 间通信`
- **次要 OWASP 对齐**：`ASI09 人-Agent 信任利用`
- **主要用途**：评审密钥、日志、存储上下文、检索数据和传输通道是否存在泄露或过度保留

---

## 2. 审计指南与定义

### 2.1 审计原则

| 原则 | 说明 |
|------|------|
| **零信任原则** | 不信任 Skill 的"不收集数据""隐私优先"声明，必须独立验证 |
| **最小披露原则** | Skills 应最小化敏感数据的收集、存储和传输 |
| **加密传输原则** | 敏感数据在传输和存储时应加密 |

### 2.2 术语表

| 术语 | 定义 |
|------|------|
| **硬编码凭证** | 直接写入源代码的密钥、密码 |
| **信息泄露** | 将敏感信息暴露给未授权方 |
| **数据脱敏** | 处理敏感数据使其无法识别原始信息 |
| **遥测数据** | 以分析为名收集的用户行为数据 |
| **长期凭证** | 不过期或难以轮换的 API Key/密码 |
| **语义凭证检测** | 通过正则 + 熵 + 上下文三阶段分析识别凭证 |
| **熵分析** | 通过随机性度量区分真实密钥和占位符 |

---

## 3. 风险类别与评级

| 风险级别 | 定义说明 | 典型场景 |
|---------|---------|---------|
| **P0（致命）** | 硬编码生产密钥，或大量用户数据泄露 | API Key 提交到 GitHub、日志含用户密码 |
| **P1（严重）** | 敏感信息明文存储或传输 | 配置文件明文存储、日志含 Token |
| **P2（轻微）** | 轻微信息泄露风险，或信息可间接推断 | 日志含内部路径、错误消息暴露系统信息 |
| **P3（提示）** | 偏离最佳实践但泄露风险低 | 注释含历史代码、调试日志未清理 |

## 4. 审计检查清单

### 4.1 代码扫描
- [ ] **检查点 1**：搜索 `api_key`、`apikey`、`api-key` 变量名
- [ ] **检查点 2**：搜索 `password`、`passwd`、`pwd`、`secret`
- [ ] **检查点 3**：搜索 `token`、`access_token`、`auth_token`
- [ ] **检查点 4**：搜索 `private_key`、`secret_key`
- [ ] **检查点 5**：检查代码注释是否包含敏感信息

### 4.2 配置文件检查
- [ ] **检查点 6**：`.env`、`.ini`、`.yaml` 配置文件是否明文存储凭证
- [ ] **检查点 7**：配置文件是否提交到版本控制
- [ ] **检查点 8**：是否使用环境变量读取敏感信息（推荐）

### 4.3 日志与输出
- [ ] **检查点 9**：日志输出是否包含敏感字段
- [ ] **检查点 10**：错误消息是否暴露系统内部信息（路径、SQL、内部网络端点 `host:port` / 端口号 / 接口地址等；端点详尽模式见 4.5 检查点 22）
- [ ] **检查点 11**：返回值是否包含未脱敏的敏感数据

### 4.4 数据传输
- [ ] **检查点 12**：敏感数据是否通过 HTTPS 传输
- [ ] **检查点 13**：敏感数据是否发送到第三方服务
- [ ] **检查点 14**：是否实施数据脱敏或加密

### 4.5 Agent 特定检查
> **参考**：[agent-audit](https://github.com/HeadyZhang/agent-audit) - OWASP Agentic Top 10 (ASI-04/ASI-05)

- [ ] **检查点 15**：**AWS Access Key ID** - 检测 `AKIA[0-9A-Z]{16}` 模式
- [ ] **检查点 16**：**OpenAI API Key** - 检测 `sk-[a-zA-Z0-9]{48,}` 模式
- [ ] **检查点 17**：**GitHub Token** - 检测 `ghp_[a-zA-Z0-9]{36}` / `gho_[a-zA-Z0-9]{36}`
- [ ] **检查点 18**：**语义分析与排除** - 排除占位符、UUID、示例值
- [ ] **检查点 19**：**MCP 环境变量暴露** - `mcp_config.json` 的 `env` 字段含敏感值
- [ ] **检查点 20**：**工具执行日志泄露** - 工具参数或返回值记录在日志中
- [ ] **检查点 21**：**长期凭证使用** - Agent/工具使用硬编码长期凭证
- [ ] **检查点 22**：**内部网络端点暴露** - 硬编码 `host:port`、接口地址、端口号、云元数据地址（如 `169.254.169.254`）等非公开网络端点；含路径、SQL 之外的网络定位信息泄露

### 4.6 个人身份信息（PII）检测
> 补 skill-quality-evaluator 安全合规-包含私隐数据（维度4-2）的通用 PII 部分（凭证类已由 4.5 覆盖）

- [ ] **检查点 22**：**邮箱地址** - 检测 `[\w.-]+@[\w.-]+\.\w+` 模式（非示例/文档邮箱）
- [ ] **检查点 23**：**手机号** - 检测中国大陆 `1[3-9]\d{9}` 及国际手机号格式
- [ ] **检查点 24**：**身份证号** - 检测 `(\d{15}|\d{17}[\dXx])` 模式
- [ ] **检查点 25**：**银行卡号** - 检测 16–19 位数字并通过 Luhn 校验
- [ ] **检查点 26**：**家庭住址/精确地理坐标** - 硬编码的具体门牌、经纬度
- [ ] **检查点 27**：**财务账户** - 证券/银行账号等个人财务标识明文

### 4.7 数据收集实践（privacy-by-design）
> 补 skill-quality-evaluator 安全合规-明文输入私隐数据（维度4-4）

- [ ] **检查点 28**：**明文索取敏感输入** - 使用 `input("请输入密码/令牌")` 等无脱敏方式索取私隐数据（应使用 `getpass` 或受控输入）
- [ ] **检查点 29**：**无加密通道收集 PII** - 在明文对话/日志中直接收集身份证、银行卡等 PII
- [ ] **检查点 30**：**缺乏隐私声明** - 未说明收集目的、范围与留存周期
- [ ] **检查点 31**：**静默收集** - 默认收集而非显式获得用户同意
