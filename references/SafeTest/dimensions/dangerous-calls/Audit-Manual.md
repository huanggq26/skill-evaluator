# 危险调用审计手册

## 1. 基本信息

- **版本**：v1.0
- **适用范围**：SpecAgent
- **审计范围**：Python Skills 中的危险函数调用
- **核心目标**：识别可能导致代码执行、数据损坏或沙箱逃逸的高风险 API 调用

### 1.1 SafeTest 中的定位

- **分类角色**：交叉技术视角，非唯一顶层分类
- **主 OWASP 对齐**：`ASI02 工具滥用与利用`、`ASI05 非预期代码执行`
- **次要 OWASP 对齐**：`ASI01 Agent 目标劫持`、`ASI08 级联失败`
- **主要用途**：追踪工具参数、模型输出或检索内容是否能转向不安全执行路径

---

## 2. 审计指南与定义

### 2.1 审计原则

| 原则 | 说明 |
|------|------|
| **描述与实质分离** | 不信任 Skill 自述声明（如"安全""无害"），必须独立验证实际代码行为 |
| **最小权限原则** | Skills 应使用完成功能所需的最小必要权限，避免过度授权 |
| **防御性审计** | 假设所有外部输入均为恶意，检查是否有充分防护 |

### 2.2 术语表

| 术语 | 定义 |
|------|------|
| **危险调用** | 可能导致任意代码执行、数据损坏或沙箱逃逸的高风险函数/API |
| **动态执行** | 在运行时解析并执行字符串代码（eval/exec） |
| **命令注入** | 用户输入拼接到系统命令中执行 |
| **反序列化漏洞** | 不可信数据的不安全反序列化导致代码执行 |
| **污点分析** | 追踪数据从 Source（工具参数/用户输入）到 Sink（危险函数）的流动 |
| **工具入口点** | 被 `@tool` 装饰或继承 `BaseTool` 的函数/类，可由 LLM 调用 |
| **沙箱逃逸** | 突破执行环境限制，访问受限资源或执行未经授权的操作 |

---

## 3. 风险类别与评级

| 风险级别 | 定义说明 | 典型场景 |
|---------|---------|---------|
| **P0（致命）** | 无条件执行任意代码，完全破坏系统安全边界 | 未过滤的 eval()、直接执行用户输入的 os.system() |
| **P1（严重）** | 存在代码执行风险，但有限制条件或部分防护 | 使用 ast.literal_eval 但逻辑有缺陷、shell=True 的 subprocess |
| **P2（轻微）** | 使用危险函数但有较完善的保护措施 | 带白名单过滤的 eval()、沙箱隔离执行 |
| **P3（提示）** | 使用可能危险的函数但风险极低 | 硬编码的 subprocess 调用（无用户输入）、开发调试用 eval |

## 4. 审计检查清单

### 4.1 代码扫描
- [ ] **检查点 1**：搜索 `eval(` 和 `exec(` 调用，检查用户输入是否被过滤
- [ ] **检查点 2**：搜索 `os.system(`、`os.popen(` 和 `subprocess` 调用
- [ ] **检查点 3**：搜索 `pickle.loads(`、`yaml.load(` 不安全用法
- [ ] **检查点 4**：搜索 `__import__(` 动态导入和 `compile(` 函数
- [ ] **检查点 5**：搜索 `shutil.rmtree(`、写入系统路径的 `open()`

### 4.2 输入验证
- [ ] **检查点 6**：危险函数是否直接接收用户输入（未转义/未过滤）
- [ ] **检查点 7**：是否存在输入白名单验证机制
- [ ] **检查点 8**：字符串在拼接到命令前是否安全转义（如 shlex.quote）

### 4.3 防护措施
- [ ] **检查点 9**：是否有沙箱隔离（如 restrictedpython、docker）
- [ ] **检查点 10**：是否有超时限制防止无限执行
- [ ] **检查点 11**：是否使用更安全的替代 API（如 ast.literal_eval 替代 eval）

### 4.4 Agent 特定检查
> **参考**：[agent-audit](https://github.com/HeadyZhang/agent-audit) - OWASP Agentic Top 10 (ASI-02)

- [ ] **检查点 12**：**工具输入污点分析** - `@tool` 装饰的函数参数是否未经验证流向危险函数
- [ ] **检查点 13**：**未沙箱化代码执行** - 工具调用 `eval()`/`exec()`/`subprocess` 无沙箱隔离证据
- [ ] **检查点 14**：**SQL 注入风险** - 工具参数直接拼接到 SQL 语句中
- [ ] **检查点 15**：**盲目信任工具输出** - 工具返回值直接用于决策或执行，未经验证

### 4.5 描述与现实对比
- [ ] **检查点 16**：**交叉验证**：对比 Skill 自述与实际代码行为
- [ ] **检查点 17**：记录任何不一致（如声称"无代码执行"但实际有 eval）

## 5. 评分标准与公式

### 5.1 评分公式

$$Score = 100 - (N_{P0} \times 40) - (N_{P1} \times 20) - (N_{P2} \times 10) - (N_{P3} \times 5)$$

- $N_{Px}$：对应风险级别的发现数量
- **最低分数**：0 分
