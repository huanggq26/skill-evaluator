# 语义漂移治理方案

> **规格声明**（LLM 自消费规格 · 强制）
> - 编写/维护者：LLM（自写自维护，含未来自己）
> - 使用者：运行中的 LLM（唯一目标读者；人可读非目标）
> - 编写牵引目标：token 最少、性能最优、不确定性最低
> - 作用：评估并设计「技能声明能力 ↔ 功能表 ↔ 技能入口文件实际内容」之间漂移的治理方案；供立项决策
> - 生成物：改造落点（`validate_function_table.py` / `auto_subjective.py` 增强）+ 本文档
> - 层级/归属：项目级方案（受 `改造方案编写规格` 约束；上游链：本文档 → 该通用规格 → `agent_spec_writing_standard`）
> - 自检锚点：改本文件前后 → 递归过 `层级/归属` 链上全部规格文件的对应自检清单，逐项核对，禁止跳过

## 目标契约

```markdown
# 任务契约 semantic-drift-governance
- 全局目标：治理「技能声明的能力 ↔ 功能表 ↔ 技能入口文件实际内容」之间的漂移；
            功能表未显式定义时给出编写建议（不警告、不错误）
- 验收标准：
  1. 英文技能样本上分词生效，不因语言误报「缺失」
  2. 零命中检测：已知臆造条目能报出；真实存在但表述不同的条目仅提示人工确认，不判漂移
  3. 既有四层校验行为不回退（退出码语义不变）
  4. 自评与外部评测行为一致（同一套逻辑与语料发现）
  5. 编写建议项不影响评分 / 门禁 / 退出码
- 范围边界：
  做：语言自适应、语料多候选发现、编写建议、零命中检测、LLM 覆盖判定的引导规则
  不做：改动既有四层校验行为、改评分与门禁、新增独立报告区、在 scripts 中查找功能来源
- 产出物：
  - `validate_function_table.py`（语言自适应 + 零命中检测）
  - `auto_subjective.py`（功能表引导材料增强，不新增 LLM 调用）
  - 本文档（方案权威源，定稿后归档）
- 约束引用：`改造方案编写规格#论证准则`、`agent_spec_writing_standard#文件编写要求`、
            `AGENTS_RULES.md`（报告输出要求）、`ERR-021`
```

## 概念与术语

脚本标识符与后续实现共用同一套命名（遵循 `改造方案编写规格#概念与术语.脚本标识符列`）。

| 术语 | 脚本标识符 | 定义 | 判别要点 |
|---|---|---|---|
| 功能表 | `function_table` | 由 LLM 归纳的、被测技能的**用户服务场景**清单 | 主观维度，须 LLM 裁定 |
| 语料 | `corpus` | 被测技能自身的自述文本（入口文件 / 自述文档 / 示例 / FAQ） | **不含** scripts 与内部实现 |
| 零命中 | `hit_zero` | 功能表某条目的特征词在语料中**一个都未出现**（hit = 0） | 疑似臆造信号，非漂移判定 |
| 覆盖率 | `coverage` | 功能条目特征词在语料中的命中比例 | 实测天花板 25–30%，**不得用于判定** |
| 编写建议 | `advice` | 对技能作者的格式引导 | 不警告、不错误、不影响门禁 |
| 臆造 | `fabricated` | 功能表中无技能依据支撑的条目 | 与 `ERR-018`（产出物当功能）同源的另一面 |

## 枚举定义

有限取值集合列全取值域，实现时直接落为枚举类型，**禁止散落字面量**（遵循 `改造方案编写规格#枚举定义`）。

| 枚举名 | 取值域 | 语义 | 默认 |
|---|---|---|---|
| `Lang` | `ZH` / `EN` / `MIXED` | 语料主语言（中文 / 英文 / 中英混合） | — |
| `HitBand` | `ZERO` / `PARTIAL` | 命中区间：零命中 / 部分命中（**不作判定**） | — |
| `DriftLevel` | `ADVICE` / `HINT` / `WARN` / `ERROR` | 输出级别：编写建议 / 提示 / 警告 / 错误 | `HINT` |

规则：

- 取值域列全；新增取值须改本表，禁止脚本临时加字面值。
- 脚本引用本表，不重新定义。

## 可行性论证

> 准则：先量化、后结论。所有数据来自真实语料实测，非估计。

### 实测一：Frontmatter / When to Use 作对照 → 不可行

| 技能 | 功能表 | description 词数 | 各条命中率 |
|---|---|---|---|
| aihot | 7 条 | 28 | `0% 25% 0% 0% 14% 0% 0%`（5 条为 0%） |
| skill-evaluator | 5 条 | 38 | `27% 0% 0% 0% 50%`（3 条为 0%） |

**结论**：不可行作对照语料。description 为 28–38 词的一句话定位，功能表为 5–7 条服务场景，**天然覆盖不了**。

**附带发现**：`When to Use` 在实测技能中**不是独立章节**，而是写在 description 内（"用户询问…时使用" / "典型触发语"）。其价值是**触发语线索**（判断能力是否用户可感知），不是覆盖率对照。

### 实测二：技能入口文件全文作对照 → 天花板 25–30%

| 技能 | 规模 | 词数 | 平均覆盖率 |
|---|---|---|---|
| aihot | 4511 字 | 481 | **29%** |
| skill-evaluator | 18622 字 | 1604 | **25%** |

**结论**：文档变长 4 倍、覆盖率反而略降 → 不是语料不足，而是**用词天然错位**：

- 功能表用概括词：`断点续跑`、`技能同行评审`
- 正文用细节词：`resume 模式`、`以报告为评审依据`

语义相同、词面不重合 → **任何基于词面重合的覆盖率判定都会误报**。

### 实测三：零命中仍有价值

| 技能 | 零命中条目占比 |
|---|---|
| aihot | 1/7 = 14% |
| skill-evaluator | 1/5 = 20% |

**结论**：量小、值得人工看一眼——"功能表里有、语料里一个相关词都没有"很可能是**臆造**。

### 实测四：异质样本来源

| 项 | 实测 |
|---|---|
| 技能市场规模 | 295 个技能目录 / **372 个 SKILL.md** |
| 英文技能存在性 | 是（抽样：`description = "Edit PDFs with natural-language instructions..."`；章节标题 `## Quick start`） |
| 中英双字段 | 存在（`description` + `description_zh`） |

**结论**：英文样本问题已解决（技能市场可取）；广泛语料源可从中提取。

### 被推翻的设计（留档，防重犯）

| 版次 | 设计 | 实测结果 | 处置 |
|---|---|---|---|
| v0 | 整体词集合比例判定（阈值 0.5） | 缺失率恒 68%–98%，样例为切词碎片 | 移除 |
| v1 | 逐条覆盖检查（阈值判定） | 覆盖率天花板 25–30%，同义改写无法区分 | **降级**为仅 `hit=0` 检测 |
| — | 硬编码 `references/USER_GUIDE.md` 作语料 | aihot 有 `api.md`/`errors.md`/`sync.md` 但无该文件 → 误报缺失 | 改为多候选发现 |

**教训**：跨载体文本比对，须先拿真实语料量化重叠率再定阈值；构造用例（三处同文）测不出此问题。

## 关键决策

```python
# 要素定义
要素:
  E1 = 功能条目特征词在语料中的命中率 hit
  E2 = 技能是否提供可比对的自述语料
  E3 = 语料主语言（中文 / 英文 / 混合）

assert E1 is not None, "命中率未取到 → 停止，提请裁决，不得默认放行"

# 裁定
if not E2:                 return "记「无」，不判缺陷"
if E1 == 0:                return "提示：未找到任何字面对应，请确认是否臆造或表述不同"
if 0 < E1 < 阈值待定:       return "不判定（天花板 25–30%，判定即误报）；交 LLM 语义层"
```

**语言路由**：

| E3 | 分词 |
|---|---|
| 中文为主（中文字符占比 ≥ 阈值） | 2-gram 滑动 |
| 英文为主 | `\b[A-Za-z]{3,}\b` 小写化 + 英文停用词 |
| 混合 | 两者并集 |

## 方案设计

```
L0  语言自适应（替换 _CJK_WORD 为 _tokens）
L1  语料多候选发现 + 功能表显式化「编写建议」
L2  语义总结（增强既有 LLM 裁定引导材料，不新增调用）
L3  机械层：仅零命中检测（防臆造），提示级
L4  语义层：覆盖判定交 LLM，须给行号证据
```

### L0 语言自适应

- 按语言路由表分词；英文停用词表需新建并实测校准。
- **动态词表**：从被测技能自身计算无区分度词（在各章节普遍出现者）并剔除——每次动态算，不预置、不绑定技能。

### L1 语料发现 + 编写建议

**发现顺序（放宽，不强制格式）**：

1. 显式功能区：任意标题含 `能力 / 功能 / 用法 / 使用场景 / When to use`（中英、大小写不敏感）
2. 自述文档：`README* / USAGE* / GUIDE* / USER_GUIDE*`
3. 回退：`{SKILL_DIR}` 下其余 `.md`
4. 兜底：`{ENTRY_MD}` 全文

找不到 → 记「无」，**不判缺陷**。

**编写建议**（挂检查子标题下，标注「编写建议」）：

> 编写建议：该技能未以独立章节显式声明所支持的功能（推荐 `## 能力` 或 `## When to use`）。显式声明有助于用户理解「能用它做什么」。本项仅为编写建议，不影响评分与上架结论。

### L2 语义总结（功能表从哪来）

**不新增 LLM 调用**——增强既有 `auto_subjective` 的功能表引导材料：

| 引导项 | 内容 |
|---|---|
| 候选来源 | **仅 `{ENTRY_MD}`**（frontmatter / 正文章节 / 示例 / FAQ）；**不查 scripts** |
| 视角规则 | 一条功能 = 一个用户可感知的服务场景；排除产出物、过程构件、内部机制 |
| 粒度规则 | 一个功能 ≠ 一条命令 / 一个文件 / 一个阶段；按用户目标归并 |
| 证据要求 | 每条附来源（章节 / 行号），无证据不得进入功能表 |

### L3 机械层：仅零命中检测

```
对功能表每条 fi：hit = |tokens(fi) ∩ tokens(语料)| / |tokens(fi)|
仅当 hit == 0 → 输出提示
```

输出措辞：

> 提示：功能「X」在技能文档中未找到任何字面对应，请确认该条目是否为臆造，或使用了完全不同的表述（如「断点续跑」vs「resume 模式」）。

**不做**覆盖率判定（实测已证天花板 25–30%）。

### L4 语义层：覆盖判定交 LLM

| 判定 | 输出 |
|---|---|
| 语料中有明确对应 | 已覆盖 |
| 有对应但表述不同 | 已覆盖（标注证据位置） |
| 找不到任何依据 | 疑似臆造（提示级，人工确认） |
| 语料有能力但未进功能表 | 疑似遗漏（提示级） |

LLM 判定**必须落到具体章节 / 行号**，可复核；不得只给结论。
