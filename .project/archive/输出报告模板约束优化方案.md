## 概念与术语

术语名与脚本标识符一一对应，文档与脚本共用同一套名字。

| 术语 | 脚本标识符 | 定义 | 判别要点 |
|---|---|---|---|
| 数据槽位 | `slot` | 模板标注声明的一个数据位（`dim` 表格型 / `field` 文本型） | 由模板标注派生，脚本禁止硬编码槽位名 |
| 槽位形态 | `slot_kind` | `TABLE` / `TEXT` | 对应 schema 的 `kind` 字段 |
| 槽位来源 | `slot_origin` | `OBJECTIVE`（脚本产出）/ `SUBJECTIVE`（LLM 裁定） | 由模板 `type` 标注唯一裁定 |
| 级别 | `level` | 问题严重度 | **改造重点**：拟从「原因」列文本反推改为结构化字段 |
| 级别常量 | `LEVEL_CONST` | 级别词与其渲染色的映射 | 当前 4 处硬编码，拟收敛为单一常量表 |
| 事实基座 | `fact_base` | `extract_stats.json`，客观事实唯一数据底座 | 脚本产物，LLM 不生成 |
| 客观映射 | `map_objective` | 事实 → 槽位 的转换（含判级） | `build_objective_data.build()` |
| 主观提示 | `advisory` | 脚本给 LLM 的复核提示，形状 `skipped=True`，**非裁定** | `auto_subjective` 产出 |
| 空槽位 | `empty_slot` | `rows` 空且 `text` 空 | 渲染为「无」；实测占比 64%–68% |
| 规则锚点 | `rule_anchor` | 槽位 ↔ 规则文档条目的机器可校验绑定 | **拟新增**；当前无绑定 |
| 依赖对 | `dep_pair` | 客观候选字段与主观裁定维度的配对关系 | 当前硬编码于 `merge_report_data` |
| 门禁 | `gate` | 数据态 / 报告态的机器校验 | `validate_quality_report` |
| 被推翻设计 | `reverted_design` | 实测或分析推翻的原设计部分 | 必须留档（见 可行性论证.留档） |
| 评分报告 | `benchmark_report` | 最后阶段产出，各项评测得分与发布门禁结论 | 消费者是决策者 / 门禁；**严禁**整改建议与问题明细 |
| 问题报告 | `problem_report` | 最后阶段产出，可整改缺陷与定位 | 消费者是开发者与 skill-doctor；**严禁**分值与上架裁决 |
| 报告职能 | `report_role` | 一份报告的职责归属：`SCORING` / `PROBLEM` | 一节只能属一种职能；跨职能内容一律改为指向对方报告 |
| 报告节 | `report_section` | 报告内一节的骨架单元（标题 / 编号 / 职能标注） | 编号由模板固定，脚本不得动态计算 |

## 关键决策

### 决策 D1：`columns` 声明唯一化路径

要素定义：

```python
要素:
  E1 = 顶部注释块内示例标注是否被派生器误抽?        # F1 实测：是
  E2 = 正文正式声明是否为唯一权威?                  # 模板自述：是（第 2 行）
  E3 = 剥离顶部注释块的渲染正则是否以整块为目标?     # render_report 步骤 3

assert E1 is not None and E2 is not None and E3 is not None, \
    "要素未取到 → 停止，提请裁决，不得默认放行"
```

| E1 误抽 | E2 正文为权威 | 裁定 | 做法 |
|---|---|---|---|
| 是 | 是 | 方案甲 | 派生器扫描前先剥离顶部注释块，再取首个 `columns` 声明 |
| 是 | 否 | 方案乙 | 删除顶部示例标注，保留正文声明为唯一 |
| 否 | 是 | 无需改造 | — |
| 否 | 否 | 提请裁决 | — |

裁定：**方案甲 + 方案乙 并行**——派生器先剥离注释块（治本），同时把顶部示例改为不会被正则匹配的形式（治标，对应 R9）。理由：仅改正则无法防御后续新增注释；仅删示例无法防御派生器先取首匹配的结构性缺陷。

### 决策 D2：级别结构化后的兼容策略

```python
要素:
  E1 = 是否存在已落盘的历史 report_data.json 需兼容?
  E2 = 汇总（objective_critical/warning）是否可同步切换?
assert E1 is not None and E2 is not None, \
    "要素未取到 → 停止，提请裁决，不得默认放行"
```

| E1 有历史数据 | E2 可同步切换 | 裁定 |
|---|---|---|
| 否 | 是 | 一次切换：rows 增加 `level` 键，同步改汇总与着色 |
| 是 | 是 | 过渡期双读：`level` 优先，缺失回退文本反推，并在门禁告警 |
| 是 | 否 | 暂缓，先做 R2/R3 |
| 否 | 否 | 提请裁决 |

裁定：**一次切换**（E1=否、E2=是）。核查依据：

| 核查项 | 结论 |
|---|---|
| 阶段 0 前半段中间产物是否每次重生成 | 是；`run_stage0` 逐步覆盖写回 `extract_stats.json` / `objective_data.json` / `report_data.json`，不存在跨版本复用旧中间数据 |
| 是否存在「只重跑后半截」的既定用法 | 存在，但仅限**同一次评测会话内**补完人工裁定后重跑，不跨版本 |
| 本技能是否已发布、有无历史结果 | 未发布，无历史前半段结果 |
| 清空工作区是否默认执行 | 否；`--reset` 为可选开关，默认只覆盖同名文件、不清目录（差异见 R11） |

| 否 | — | 删除 |
| 是 | 部分 | 逐条分流：被覆盖者删，未覆盖者恢复 |

### 决策 D5：最后阶段报告模板化路径

其中 `.gitignore` 里的 `/tmp/` 是忽略临时目录的正常写法，非缺陷；机器仍按规则判为警告。根因是**扫了不该扫的文件**，归 R12。

R10 真正要分离的是另一类——机器**完全没给结论**、报告却同样写「无」的槽位：

| 槽位 | 机器留下的线索 | 报告当前显示 | 读者易误读为 |
|---|---|---|---|
| `content_correct` | 内容正确性需 LLM 语义复核（字数线索：name 12 / description 201 / 正文 10444） | 无 | 内容正确无误 |
| `eco_placement` | 分类与关联需 LLM 语义复核；可移植性客观线索：机器路径 3 / 非 env shebang 0 / CRLF 0 | 无 | 分类放置没问题 |
| `modalities` | 多模态能力需 LLM 基于 SKILL.md 归纳（客观线索：正文 10444 字） | 无 | 不涉及多模态 |

三者均**未产出任何问题行**，与「查过确实没问题」渲染完全一致——这才是 R10 要消除的歧义。

| 候选 | 报告呈现 | 复核者要做的事 |
|---|---|---|
| 甲 | `待人工裁定` | 自行翻源文件找线索 |

| 丙 | 乙 + `依据材料见 {QUALITY_RESULTS_DIR}/subjective.json` | 直接翻到线索，不必重扫 |

### 主观槽位为何为空：根因是分工与闭环，不是能力问题

| 层 | 结论 | 依据 |
|---|---|---|
| 脚本为何不判 | **纪律约束**：脚本填语义结论 = 编造结论 | `auto_subjective.py` 明写「不以脚本结论冒充裁定」；`run_eval_pipeline.sh` P7 注释「脚本自动填充等同于编造结论（违反不臆造纪律）」 |
| 谁应当判 | **执行评测的 LLM 本体** | `SKILL.md`「AI 回填（报告生成，由本 agent 执行）」为阶段 0 第 4 步：读模板 + 事实基座 → 生成 `subjective.json` → 合并 → 校验 → 渲染 |
| 实测为何全空 | 一键流水线 `run_stage0` **自带** merge + render，在 LLM 补做裁定**之前**即产出报告；补做属流程外步骤，未执行则**静默降级** | `run_eval_pipeline.sh` `run_stage0` 末段；`auto_subjective` 仅在 `subjective.json` 不存在时才生成 advisory |

结论：非疏忽、非能力不足，而是「脚本不做语义裁定」的职责分工 + 「补做依赖执行者」的闭环设计；补做缺失时**不报错、不提示**，仅静默渲染为「无」——这正是 R10 要暴露的静默降级。

**R16 实施中发现并修复的真 bug**：`_strip_top_comment_block` 的正则把块内**内嵌注释**的 `-->` 当成块尾，导致注释块剥离提前终止、残留注释正文污染扫描。阶段 4 模板顶部含内嵌示例故触发；**阶段 0 模板因 R9 已先修复而未触发**——两者互为印证。修复方式：`-->` 必须独占行尾才算块尾。阶段 0 回归无影响（R4 28/28、报告 112 行）。

**实施手法说明（R1）**：采用「生成时固化 `level`、下游只读 `level`」的最小改法——级别词 → level 的映射收敛到 `_level_from_text()` **一处**，无需改动 17 处 `_row` 调用点；`_severity_of` 保留文本回退仅作**安全阀**（兼容 LLM 填写的主观行），客观侧严格读 `level`。
