# 重跑后人工补充恢复清单

> **触发时机**：每次 `--reset --mode full` 重跑后。
> 报告由脚本重新生成，**所有人工补充都会被覆盖**。
> 本清单用于逐项检查补救，避免"重跑一次、丢一批分析结论"。

## 一、检查项

| # | 位置 | 内容 | 适用范围 |
|---|---|---|---|
| 1 | `quality/<被测技能>评测.md` | **功能表归纳**（替换「待 AI 语义归纳」占位，ERR-014） | **每个被测技能各一份** |
| 2 | `spec/problem_report.md` | 根因分析节（症状 ≠ 根因，需人工取证后补充） | 有失败项时 |
| 3 | `spec/problem_report.md` | 文档完整性提醒（如 When to Use 缺失） | 通用 |

## 二、⚠️ 易错点（均已发生过）

**1. 只恢复一个技能，漏掉另一个**（2026-09-08 实例）
自评（`skill-evaluator`）与被评（`aihot`）是**两份独立报告**，
各自的功能表都要归纳。曾只补了 aihot，自评那份留着空占位。

**2. 以为索引库能兜底**
`errindex.db` 只存**首行字段**（`_field()` 仅取首行），
「误判史」「关联」等根本没入库，**不能当备份**（ERR-019）。

**3. 用 `write_to_file` 覆盖已有档案**
新增记录一律 `replace_in_file` 追加，禁止整体覆写（ERR-019）。

**4. 数据源可能变化，旧结论需复核**
例：`hot-topics` 曾返回 0 条（据此判定技能缺降级逻辑），
后续复测返回 4 条。**已给出的建议未必失效，但须注明时效**（防御性建议仍然有效）。

## 三、操作顺序

1. **重跑前**：备份含人工补充的报告 → 登记备份（含预定删除条件）
2. **重跑后**：按上表逐项检查，缺失即补
3. **恢复后**：`errindex rebuild` + `errindex check`
4. **验证通过**：按登记删除备份，更新登记状态
