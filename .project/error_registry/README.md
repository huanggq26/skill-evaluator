# 错误档案区（error_registry）

> 定位：`project_spec_maintenance.md` 项目治理方案的**补充件**。
> 归属判定（内容归属三问）：`E2`（会无限递增）= True
> → **必须独立成区，禁止塞进规则层**。

## 为何存在

LLM 上下文易失，导致两类失效：

| 失效模式 | 实例 | 本区对策 |
|---|---|---|
| **遗忘修改史 → 错误轮回** | 同一现象连犯 4 次归因错误 | 强制查档，历史外置持久化 |
| **证据不全就断言** | 只读报告即下结论 | 强制写「前提/依赖」，前提不成立不得结论 |

**核心：把「我犯过的错」变成可检索资产，不再依赖我这次记不记得。**

## 目录结构

```
error_registry/
├── README.md          本文件：规范
├── ERRCODE.md         标签表（唯一权威）
├── INDEX.md           全量索引（一行一条）
├── errindex.py        检索服务（内容仍以 md 为准）
├── errindex.db        派生索引（不入版本控制，可 rebuild）
├── by_module/         【纵】阶段–模块–函数
│   ├── _cross_cutting.md
│   └── S3__exec_functional_tasks.md
└── _archive/          【横】退出区
    ├── INDEX.md
    └── ERRLOG_YYYY-MM.md
```

- **纵**（`by_module/`）：阶段 → 模块 → 函数，答「**哪里**错了」
- **横**（按标签聚合）：同类错误跨模块，答「这类错还**在哪**犯过」

## md 记录格式（权威源，须严格遵循）

```markdown
# S3 / exec_functional_tasks

## exec_one() — 一句话现象

- **ID**: ERR-004
- **标签**: `E01` `E02` `E31` `#误判史` `#待验证`
- **状态**: active
- **发现**: 2026-09-07
- **现象**: 具体表现
- **前提/依赖**: 该结论成立所依赖的条件
- **归因**: 根因
- **修改策略**: 怎么改
- **验证方式**: 如何确认修好了
- **误判史**:
  - ✗ 曾误判为……（推翻的理由）
```

**函数可选**：无具体函数时标题直接写现象，不写 `()`。

## 关联与修订（改动溯源）

> 场景：某次改动之后又出问题——新问题如何挂到旧改动上？
> 若旧改动本身被证明是错的，如何留下教训？

### 关系类型（单向声明，反向自动生成）

只需在**新记录**声明，反向关系由 `errindex` 自动推导（避免双向维护漂移）：

| 关系 | 写法 | 含义 | 自动生成反向 |
|---|---|---|---|
| 引发 | `关联: ERR-006（caused-by）` | **本问题由那次改动引入**（副作用 / 回归） | ERR-006 显示 `caused: 本条` |
| 取代 | `关联: ERR-006（supersedes）` | **本记录取代那次结论 / 策略**（旧改动被证伪） | ERR-006 显示 `superseded-by: 本条` |
| 根因 | `关联: ERR-005（root-of）` | 本记录是那问题的根因 | ERR-005 显示 `caused-by: 本条` |
| 相关 | `关联: ERR-002（related）` | 一般关联 | 双向对称 |

查看完整关联链：`errindex show <ID>`

### 旧改动被证伪时的处置

**原则：历史不改写，只追加修订**（沿用治理规范「只追加不修改」纪律）。

1. **不动**旧记录的「归因」「修改策略」——它记录的是**当时**的判断，抹掉即失去教训
2. 旧记录补 `修订: ERR-013（本策略经证伪）` 并贴 `#证伪` 标签，状态转 `superseded`
3. 新记录（ERR-013）写 `关联: ERR-006（supersedes）`，
   「归因」说明**旧改动错在哪**，「误判史」记录这次认知推翻

> **为何不改写**：改写后后来者只看到"现在正确的版本"，
> 看不到"曾经错在哪"——而后者才是防重蹈的关键。
> `#证伪` 可一次检索出**所有「我以为改对了、其实改错了」的记录**，
> 是全库教训密度最高的集合。

## 读写纪律（强制 · 双向）

```python
# 诊断前查档——阻断式
步骤:
  1. errindex q --module <模块> [--func <函数>]      # 纵：定位
  2. 从命中记录提取 tags
  3. errindex q --tag <每个标签>                      # 横：同类跨模块
  4. 按 file_path 打开 md 读原文（含误判史）
  5. 逐条核对「前提/依赖」是否仍成立
assert 已完成 1-5, "未完成查档 → 停止，不得诊断下结论"
```

**效率让位于正确性**：本流程强制，即使降低效率。
违反即记 `E31`（未查档即诊断）入档。

> ⚠️ 检索只回答「去哪读」，**必须打开 md 读原文**——
> 把摘要当结论，正是 `E01` 的病根。

### 写入侧：问题解决时必须同步建档（对称强制）

**触发时机（任一即须写）**：

| 时机 | 写什么 |
|---|---|
| 定位到根因 | 补「归因」「修改策略」「验证方式」 |
| 实施修复后 | 补验证实测结果，状态转 `fixed` |
| **归因被推翻** | **追加「误判史」一行**（最高价值，防重蹈） |
| 前提失效 | 标记退出，按第七节归档 |
| 发现新错误 | 新建记录（新 ID） |

**硬约束**：

- **不写档案 = 任务未完成**，不得标 `DONE`
- 写完须 `errindex rebuild` + `check` 通过（保证路径有效）
- 新标签须先在 `ERRCODE.md` 登记再使用

> **读档防重蹈，写档防遗忘**——只做一半等于没做：
> 读了不写，下次历史依然空白，错误轮回照旧。

## 检索命令

```bash
errindex rebuild                      # 全量重建（幂等）
errindex q --module X                 # 仅模块（函数可选）
errindex q --module X --func exec_one # 精确到函数
errindex q --tag E01 --tag E02        # 组合标签 AND
errindex q --tag E01 --tag E02 --any  # 组合标签 OR
errindex q --module X --tag E01       # 模块 + 标签组合
errindex q --meta '#误判史'            # 元标签
errindex stats                        # 标签分布，浮现 #系统性
errindex check                        # 一致性校验
```

## 索引—内容 生存期管理（强制）

**原则：md 是权威源，SQLite 是派生索引，二者生命周期必须一致。**

| 机制 | 说明 |
|---|---|
| **全量重建** | `rebuild` 先删库再重扫，md 删除后索引项随之消失 |
| **路径校验** | 查询时校验 `file_path` 存在性，悬空记录自动过滤并告警 |
| **一致性校验** | `check` 报告悬空 / 遗漏 / 幽灵三类不一致 |
| **不单独删索引项** | 要删就删 md，再 rebuild |

**检索出来的路径必须符合实际**——这是硬要求。

## 退出条件（防无限膨胀）

| 条件 | 判定 | 动作 |
|---|---|---|
| 已修复稳定 | 连续 3 次完整评测未复现 | `active`→`fixed`，移入 `_archive/ERRLOG_YYYY-MM.md` |
| 前提失效 | 函数删 / 阶段重构 / 依赖下线 | 归档留痕 |
| 被更优方案覆盖 | 更根本修复包含它 | 合并后删旧 |
| **误报** | 问题本身不存在 | ⚠️ **压缩成「误判史」一行，不整体删** |
| 超期 | 30 天未复现且无 active 关联 | 归档 |

**为何误判史不删**：它记的不是"系统哪坏了"，而是"**我会怎么想错**"。
删掉它，错误轮回必然重演——**这是本区最值钱的资产**。

**膨胀控制**（沿用归档四道控制）：
归档时精简（只留目标+结果+教训）· 按时间分卷 · 单卷 >400 行细分 · 维护 INDEX。

## 版本控制

| 对象 | 处理 | 判据 |
|---|---|---|
| `*.md`（权威源） | **入库** | 有备份价值，无法重建 |
| `errindex.db` | **过滤** | 派生物，`rebuild` 可重建 |
| `errindex.py` | **入库** | 检索服务本体 |

符合治理方案 `.gitignore` 判据：**有无备份价值，而非文件类别**。
