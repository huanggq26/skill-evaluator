## 报告输出「待 AI 归纳」占位符，并要求读者去读内部数据文件

- **ID**: ERR-014
- **标签**: `E22` `#待验证`
- **状态**: active
- **发现**: 2026-09-08
- **现象**: 质量报告「功能表」章节输出：
  ```
  _待 AI 语义归纳服务场景_（脚本不代为裁定）：依据层次为 ①frontmatter
  description → ②When to Use → ③过程中的服务声明，完整材料见
  `quality/results/subjective.json` 的 `function_table.skip_reason`
  ```
  ——把**未完成的作业留给报告读者**，并指向中间产物文件
- **前提/依赖**: 报告由 `render_report.py` 渲染 `quality/results/subjective.json`
- **归因**:
  - 报告模板对「需 AI 语义裁定」的维度**直接输出占位符 + 内部路径**，未做整合
  - 中间产物（`quality/results/*.json`）本属实现细节，不应出现在面向人的报告中
- **影响**:
  - 报告**不自足**：读者必须翻内部 JSON 才能看到本该直接呈现的内容
  - 暴露中间产物路径会造成耦合，路径变更即悬空引用
  - 本次实际代价：需人工读取 `skip_reason`，再归纳出 7 类服务场景才补全报告
- **修改策略**:
  - 短期（**已执行**）：人工归纳后写入报告功能表，并标注依据来源与缺失项
  - 治本（待评估）：凡标注「待 AI 归纳」的维度，报告应二选一
    1. **在生成流程中完成归纳后再出报告**（推荐——报告应自足）
    2. 若确需留白，须在报告内**直接给出材料摘要**，
       **不得**指向内部中间产物路径
- **验证方式**: 报告中不再出现「待 AI 归纳 + 内部文件路径」的组合
- **复现实证（2026-09-08 下午 · ERR-018 治本回归时）**: `--reset` 重跑自评后
  subjective.json 被重新生成为 advisory（上轮已裁定内容被清掉），管线 exit 0 后
  AI 执行者**未接续裁定**即宣布任务完成 → 质量报告功能表再次输出占位符；
  另暴露 benchmark §4 功能名列因 `intent[:40]` 硬截断出现尾部悬空（「质量 /」）。
- **新根因（与原条目互补）**: 原条目是渲染层缺陷（占位 + 内部路径，短期已修）；
  本次是 **AI 执行者流程失职**——管线已生成 PENDING_AI_ADJUDICATION（15 个待裁定
  维度，输出中明确提示），却把「管线 exit 0」误当「评测完成」，未履行 P7 裁定职责。
  **管线跑通 ≠ 评测完成**：报告自足（功能表已裁定、无占位）才是完成态。
  （同源教训：ERR-018 验收只对照了自身标准「§4 无产出物」，未对照「评测完成」
  的完整定义——验收范围过窄是直接诱因）
- **修正已执行（2026-09-08）**: ① AI 裁定 function_table（5 条服务场景：
  端到端基准评测 / 仅静态质量预检 / 断点续跑 / 技能同行评审 / 使用咨询答疑）
  写回 subjective.json + 重渲染，validate_function_table 全通过（服务场景视角 +
  与 description 同源）；② extract 新增 `_short_title`（分隔符处断开）修 §4 截断，
  aihot 10 条回归仍逐字节一致。
- **遗留**: PENDING 清单其余 14 个主观维度（grammar / content_* / deps_* 等）
  仍未裁定，质量报告对应维度仍为 advisory 提示——报告完整自足需全量裁定（后续任务）
- **误判史**: 无
- **关联**: 与 ERR-013 同属「**评测侧输出质量**」族——
  ERR-013 是"只给症状不给根因"，本条是"只给占位不给内容"，
  共同点是：**报告不承担责任，把工作转嫁给读者**
