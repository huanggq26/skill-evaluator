## 报告输出「待 AI 归纳」占位符，并要求读者去读内部数据文件

- **ID**: ERR-014
- **标签**: `E22` `#待验证`
- **状态**: active
- **发现**: 2026-09-08
- **现象**: 质量报告「功能表」章节输出：
  ```
  _待 AI 语义归纳服务场景_（脚本不代为裁定）：依据层次为 ①frontmatter
  description → ②When to Use → ③过程中的服务声明，完整材料见
  `quality/results/subjective.json` 的 `function_table.skip_reason`
  ```
  ——把**未完成的作业留给报告读者**，并指向中间产物文件
- **前提/依赖**: 报告由 `render_report.py` 渲染 `quality/results/subjective.json`
- **归因**:
  - 报告模板对「需 AI 语义裁定」的维度**直接输出占位符 + 内部路径**，未做整合
  - 中间产物（`quality/results/*.json`）本属实现细节，不应出现在面向人的报告中
- **影响**:
  - 报告**不自足**：读者必须翻内部 JSON 才能看到本该直接呈现的内容
  - 暴露中间产物路径会造成耦合，路径变更即悬空引用
  - 本次实际代价：需人工读取 `skip_reason`，再归纳出 7 类服务场景才补全报告
- **修改策略**:
  - 短期（**已执行**）：人工归纳后写入报告功能表，并标注依据来源与缺失项
  - 治本（待评估）：凡标注「待 AI 归纳」的维度，报告应二选一
    1. **在生成流程中完成归纳后再出报告**（推荐——报告应自足）
    2. 若确需留白，须在报告内**直接给出材料摘要**，
       **不得**指向内部中间产物路径
- **验证方式**: 报告中不再出现「待 AI 归纳 + 内部文件路径」的组合
- **误判史**: 无
- **关联**: 与 ERR-013 同属「**评测侧输出质量**」族——
  ERR-013 是"只给症状不给根因"，本条是"只给占位不给内容"，
  共同点是：**报告不承担责任，把工作转嫁给读者**
