## 枚举占位取首项，首项无数据导致误判为技能缺陷

- **ID**: ERR-015
- **标签**: `E13` `#误报`
- **状态**: fixed
- **修复（2026-09-08）**: 新增 `_enum_values` / `_enum_variants`，
  在执行层实现「**空结果回退**」——首项取值返回空时，
  按枚举中的其他合法取值依次重试，并在 `notes` 中**记录回退痕迹**。
  → FT07 由 0 分转为 **10/10 通过**（`window=24h` → `7d`，返回 7 条）；
  功能任务整体 **7/10 → 8/10**。
- **实现期缺陷（已修，留档）**: 初版基于**含占位的原始模板**生成候选，
  导致候选残留 `<slug>` 等未解析占位符，拼出的 URL 不可用。
  修正为基于**已解析 endpoint**、仅替换枚举值本身。
  ——**单元验证先于全流程执行**，正是它拦下了这个缺陷。
- **发现**: 2026-09-08（A1 修复后重跑暴露）
- **现象**: FT07 经 A1 修复后已能真实调用，但评审仍 0/10，
  并在 `problem_report` 中被列为**被测技能的功能任务问题**（10 条 rubric）。
- **前提/依赖**: URL 模板含枚举占位 `window=<24h|7d>`
- **归因（实测）**:

  | 实际调用 | 结果 |
  |---|---|
  | `?category=paper&window=24h`（取枚举**首项**） | **0 条** |
  | `?category=paper&window=7d`（另一合法取值） | **7 条** ✅ |

  评测器按约定取枚举首项，而首项恰无数据 → 评审 0 分
  → **被记为技能缺陷**（与 ERR-012 同型的归责错误再次出现）
- **影响**: aihot 再次背锅——报告显示其"功能任务问题 20 个"，
  其中 FT07 的 10 条**并非技能缺陷**。
  本次靠人工核对才发现（已在报告中补「FT07 归责更正」节）
- **修改策略**: 枚举占位不应只取首项——
  应在首项返回空时，**回退尝试其他合法取值**（通用做法，不绑定具体技能）
- **验证方式**: FT07 应在 `window=7d` 下取到数据并通过评审
- **误判史**:
  - ✗ 一度以为 A1 修复后 FT07 即可通过——忽略"取到值"与"取到**有数据的**值"是两件事
- **关联**: ERR-012（supersedes 关系不成立，本条为其**后续暴露**的下一层问题）
