# dependency-availability Specification

## Purpose

定义依赖可用性评分的计入对象、上架否决的触发条件，以及随包资源问题的呈现责任：可用性评分只反映**外部运行时依赖**（端点可达性、认证、配额）；随包文件完整性不参与该评分与上架否决，但其探测到的**缺失或不可读必须在质量报告中呈现并提示改进**。

## Requirements

### Requirement: 可用性评分只统计外部运行时依赖

系统 MUST 仅依据外部运行时依赖的探测结果计算可用性评分；随包文件（技能目录内随分发的本地文件）的探测结果 MUST NOT 计入该评分。

#### Scenario: 外部依赖全部通过、随包文件不可读

- **WHEN** 某技能的外部依赖探测全部通过，且存在 1 个随包文件因编码或权限问题不可读
- **THEN** 可用性评分为满分，不因该随包文件降级

#### Scenario: 外部依赖存在失败

- **WHEN** 外部依赖中有若干项探测失败（非契约缺陷类）
- **THEN** 可用性评分按既有外部口径降级，且不因随包文件状态进一步降级

### Requirement: 随包完整性不触发上架否决

随包文件的缺失或不可读 MUST NOT 触发结构性否决（上架否决）；否决 MUST 仅由外部依赖的契约缺陷类问题触发。

#### Scenario: 随包文件缺失或不可读

- **WHEN** 某技能的随包文件被探测为缺失或不可读
- **THEN** 结构性否决为假，该技能不因随包完整性被否决上架

### Requirement: 随包探测结果独立承载并作为质量报告来源

系统 MUST 保留随包文件的探测，并将其结果输出到**独立于可用性维度**的字段；该结果 MUST 包含路径、状态与原因，并 MUST 作为质量报告「随包资源完整性」小节的数据来源。

#### Scenario: 存在但不可读的随包文件

- **WHEN** 某随包文件存在但读取失败（编码或权限问题）
- **THEN** 该结果出现在独立字段中并标注不可读原因，且不作为可用性评分的计算输入

### Requirement: 随包问题必须在质量报告中呈现

系统 MUST 在质量报告（阶段 0 评测报告）的「随包资源完整性」小节中呈现随包资源的探测问题；MUST NOT 因随包项移出可用性维度而丢失该提示。该提示 MUST 注明**不否决上架**。

#### Scenario: 随包文件不可读

- **WHEN** 某随包文件存在但读取失败（编码或权限问题）
- **THEN** 质量报告列出该文件路径与原因，级别为**警告**，并注明不否决上架

#### Scenario: 随包文件缺失

- **WHEN** 某随包文件被探测为缺失
- **THEN** 质量报告列出该文件路径，级别为**严重**，并注明不否决上架

#### Scenario: 随包资源全部正常

- **WHEN** 所有随包文件均存在且可读
- **THEN** 该小节呈现为"无"，不输出空表

### Requirement: 计数口径自洽

报告中呈现的外部依赖通过数与失败数 MUST 只统计外部维度；二者之和 MUST NOT 超过外部依赖总数。

#### Scenario: 随包项与外部分项并存

- **WHEN** 某技能有 N 项外部依赖与 M 项随包文件
- **THEN** 报告中呈现的外部通过数与失败数之和不超过 N，不出现通过数大于外部总数的情形

### Requirement: 无外部依赖判定为不适用而非缺失

当技能未声明任何外部依赖时，系统 MUST 将可用性维度判定为**不适用**（N/A），MUST NOT 因"未探测到外部依赖"判定为缺失、失败或否决。

#### Scenario: 仅有随包资源、未声明外部依赖

- **WHEN** 某技能只声明随包资源、未声明任何外部依赖
- **THEN** 可用性维度标记为不适用，不产出惩罚性评分，且不触发 REJECT

### Requirement: 可用性探测结果的阻断边界

可用性探测结果用于**记录依赖状态**，其消费规则为：仅**契约型缺陷** MUST 阻断后续阶段并触发否决；**环境/瞬态**失败、**配置待补**（含模板化端点与**鉴权类失败 401/403**）MUST NOT 阻断，须记录后继续执行阶段 1→4，其不可达性作为评测结果（环境限制或待补项）体现，而 MUST NOT 作为跳过阶段的理由。

> **鉴权类失败（401/403）为什么不阻断**：DEP-AVAIL 分层中，`D1 connectivity` 的验证目标是**端点存活 / 链路可达**。401/403 意味着请求已完成 DNS 解析、连接建立与 HTTP 往返并获得服务端响应——**链路已通、端点存活即已证明**；未能取得业务数据源于**鉴权未通过**（属 `D5 credential` 层面）。因探活为**匿名请求**（不带凭证），此情形即 spec 裁决策略中的 `config missing`（"需凭据但**未配置**"），其规定即为**不否决、记为未配置、提示补配置**。故 MUST 归为配置待补，不计入失败数（因而 MUST NOT 拉低可用性评分）、MUST NOT 触发否决与阻断。
>
> **边界**：本条适用于**未提供凭证**的情形；若已提供凭证却被拒（凭证无效），仍属配置或契约缺陷，维持既有判定。

> 本条**不修改**探测的类别判定逻辑，只明确既有结果的消费规则——消除"探测未过即全流程停止"的误解。

#### Scenario: 端点不可达属环境问题

- **WHEN** 探测结果为环境/瞬态失败（如连接超时、网络不可达）
- **THEN** 不阻断、不否决；继续执行阶段 1→4，并在评测产物中记录为环境限制

#### Scenario: 依赖配置待补

- **WHEN** 探测结果为配置待补（如端点为模板化基路径、需补具体示例）
- **THEN** 不阻断；继续执行阶段 1→4，并在评测产物中记录待补项

#### Scenario: 鉴权类失败

- **WHEN** 探测返回 401 或 403（请求已到达，但凭证缺失或无效）
- **THEN** 归为配置待补：不阻断、不否决、不计入失败数（不拉低可用性评分），并在提示中要求补凭证后重测；MUST NOT 归为契约型缺陷而阻断全流程

#### Scenario: 契约不成立

- **WHEN** 探测结果为契约型缺陷（返回结构与声明不符、永久不可用、凭证校验失败）
- **THEN** 按既有闸门阻断，并给出失败原因与修复建议（阻断行为保持不变）

#### Scenario: 探测未执行

- **WHEN** 因未执行探测而无探测结果
- **THEN** MUST NOT 据此推断依赖不可达；须补执行探测或实际尝试执行后据实判定
