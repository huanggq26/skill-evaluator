# pipeline-execution-integrity Specification

## Purpose
约束评测流水线必须**完整执行**（不得因主观推断或依赖状态跳过阶段与任务），并在每个阶段结束与全流程终态向用户**明确告知**进度、产物位置与下一步，使"评测是否跑完、产物在哪、接下来做什么"对使用者始终可见。

## Requirements

### Requirement: 禁止未实测的不可达推断

评测执行者 MUST NOT 在未实际探测或实际尝试执行的情况下，依据域名、环境名、网络位置、部署区域等特征推断依赖不可达或任务无法执行。任何"不可用 / 无法执行"的结论 MUST 以实际探测或实际尝试执行所产生的证据为依据。

#### Scenario: 内部域名依赖

- **WHEN** 被测技能声明的端点为内部域名（含 uat / 内网 / 企业域名等特征）
- **THEN** 必须执行实际探测或实际尝试执行，据真实结果判定；禁止据域名特征推断不可达

#### Scenario: 未声明外部依赖

- **WHEN** 被测技能未声明任何外部运行时依赖
- **THEN** 可用性维度判为不适用，但阶段 1→4 仍须完整执行，MUST NOT 以"无依赖"为由跳过

### Requirement: 执行尝试强制

每个功能任务 MUST 至少尝试执行一次。执行失败 MUST 记录任务标识、失败类型、错误信息与尝试时间，且 MUST NOT 导致后续任务或后续阶段被跳过。

#### Scenario: 任务执行失败

- **WHEN** 某功能任务执行返回错误（超时 / 连接拒绝 / 服务端错误）
- **THEN** 记录失败原因并继续执行剩余任务；全部任务完成后，在评测产物中体现失败项与失败率

#### Scenario: 连续失败

- **WHEN** 多个任务因同一环境原因连续失败
- **THEN** 继续尝试至任务穷尽，并在产物中将该原因归为环境限制；MUST NOT 中途放弃执行

### Requirement: 阶段过渡强制

阶段 0 通过后 MUST 进入阶段 1，并按序执行至阶段 4。MUST NOT 因依赖不可达、被测技能质量低、功能简单、执行环境差异等理由跳过任一阶段。

#### Scenario: 阶段 0 门禁通过

- **WHEN** 阶段 0 门禁通过
- **THEN** 必须进入阶段 1，并在阶段 1→4 全部执行后完成评测

#### Scenario: 阶段 0 门禁未过

- **WHEN** 阶段 0 门禁未过
- **THEN** 按既有闸门停止，并给出失败原因、解决方案与产物位置（阻断行为保持不变）

#### Scenario: 阶段 2/3 未执行

- **WHEN** 因任何原因阶段 2/3 未实际执行
- **THEN** 评测产物 MUST 显式标注该阶段未执行及其原因；MUST NOT 静默产出看似完整的评测结果

### Requirement: 阶段完成告知契约

每次阶段结束 MUST 向用户输出以下五项：① 进度（已完成阶段序号 / 总阶段数）；② 本阶段产物文件清单及其**绝对路径**；③ 下一步动作与**可执行的具体命令**；④ 若需用户确认，MUST 显式询问；⑤ **若流程因故无法继续而停下**，MUST 指明用户该看哪个文件 / 哪段信息以判断原因，以及用户接下来要做什么（含具体命令或操作）。

#### Scenario: 阶段 0 完成且本次仅要求预检

- **WHEN** 以仅开始阶段模式完成阶段 0
- **THEN** 须告知"仅完成阶段 0（预检），全流程尚有阶段 1→4 未执行"、质量报告的绝对路径、以及继续全流程所需的具体命令

#### Scenario: 中间阶段完成

- **WHEN** 完成阶段 1 / 2 / 3 中任一阶段
- **THEN** 须告知当前进度、本阶段产物绝对路径与下一步动作

### Requirement: 全流程终态告知

阶段 4 完成后 MUST 输出"全部阶段完成"提示，并给出**交付物清单**，其中包含两类：① 最终交付物（质量报告、基准报告、问题报告）的**文件名与绝对路径**；② **各阶段卡点的中间产物**（证明流程确实逐级执行，而非跳步产出最终报告）。MUST NOT 仅给出目录或不给出位置。

> 中间产物是流程执行的保证：最终报告是人消费的对象，而**过程正确是结果可信的基础**——缺任一阶段卡点产物，即表明流程未完整执行，MUST 显式暴露而非视为完成。

#### Scenario: 全流程正常完成

- **WHEN** 阶段 4 聚合完成且最终报告齐备
- **THEN** 输出全部完成提示，并逐项列出最终交付物与各阶段卡点中间产物的文件名与绝对路径

#### Scenario: 中间产物缺失

- **WHEN** 最终报告齐备但缺少某阶段卡点的中间产物
- **THEN** 必须显式指出缺失的阶段与产物，并判定流程未完整执行；MUST NOT 因最终报告存在而视为完成

#### Scenario: 最终报告缺失

- **WHEN** 因中间产物缺失导致最终报告未生成
- **THEN** 必须显式告知缺失内容与补救命令；MUST NOT 静默结束

### Requirement: 执行推进由探测结果驱动而非推断驱动

阶段是否继续推进 MUST 由**可用性探测或实际执行的真实结果**决定，MUST NOT 由执行者依据端点特征、域名、环境名、部署位置等做出的推断决定。

#### Scenario: 探测可达

- **WHEN** 可用性探测结果为可达（依赖正常响应）
- **THEN** 必须继续执行后续功能与性能测试，形成"探测通过 → 执行"的确定链条

#### Scenario: 探测失败但非契约型缺陷

- **WHEN** 探测失败且类别为环境问题（超时 / 网络不可达 / 服务端错误）或配置待补（模板化端点 / 缺凭证）
- **THEN** 不阻断，继续执行后续阶段，并将失败如实记录为环境限制或待补项

#### Scenario: 探测判定为契约型缺陷

- **WHEN** 探测判定为契约型缺陷（端点结构与声明不符）
- **THEN** 按既有闸门阻断，并给出失败原因、涉及文件与修复建议

#### Scenario: 未执行探测

- **WHEN** 未执行可用性探测
- **THEN** MUST NOT 以任何特征推断依赖不可达；须补执行探测或实际尝试执行后据实推进

### Requirement: 全流程请求的模式选择

用户表述为全面 / 全流程 / 完整评测时，评测 MUST 以能跑完阶段 1→4 的模式执行。MUST NOT 仅完成阶段 0 即结束而未告知如何继续。

#### Scenario: 用户要求全面评测

- **WHEN** 用户请求对某技能进行全面 / 全流程评测
- **THEN** 须执行至阶段 4，并在终态给出交付物清单

#### Scenario: 用户仅要求预检

- **WHEN** 用户仅要求质量预检
- **THEN** 可只执行阶段 0，但 MUST 按阶段完成告知契约说明"仅预检"及继续命令
