# 变更提案：评测运行与质量报告的三处一致性修复

## 背景（Why）

2026-10-12 本地 aihot 全流程实测（修复 E29 阻断后）暴露三处**运行期一致性问题**。
三者均不属功能缺陷，但会**误导使用者对评测结论的判断**——在发布前必须消除。

| # | 现象 | 为什么是问题 |
|---|---|---|
| ① | 流水线打印「✅ 全部阶段完成（进度 5/5）」，同一行上下文里又打印「⛔ 阶段 0 DoD 未满足」，最终 `EXIT=1` | 自相矛盾的输出 + 退出码。「全部完成」与「EXIT=1」同时出现，使用者无法判断这次跑成功没有 |
| ② | 质量报告「调用其他 Tools」显示「无（文档未提及）」 | 该文本是**客观候选字段**（`deps_tools_candidates`），而对应的主观维度 `deps_tools` 实际为 `skipped=True`。同一报告里另 10 个未裁定主观维度渲染为「未检查」，此处却渲染成读起来像结论的候选文本——**呈现口径不一致**，会被误读为「该技能无工具依赖」 |
| ③ | `skill-evaluator_results/aihot/` 下累积 4 个目录（`aihot_local_v1/v2`、`aihot_full_v1/v2`），编号无规则 | `WS=$RESULTS_ROOT/$SKILL_NAME/$RUN_ID`，run-id 默认时间戳、可传任意字符串，`R11` 只清本次 `$WS` → **目录无限累积、编号无规则**，只能靠 `LATEST.json` 与 mtime 判断哪个最新 |

## 目标契约

1. **输出自洽**：阶段产物已齐但 DoD 未满足时，**不得**宣告「全部阶段完成」；退出码语义保持（DoD 未满足仍为非 0），但文案明确区分「产物已齐 / 结论不完整」与「流程失败」。
2. **呈现一致**：主观维度未裁定时，报告中**不出现**读起来像裁定结论的客观候选文本；候选文本须带「待 AI 裁定」标记。
3. **编号有规则**：run-id 缺省时按 `v<N>` 递增；显式传入时校验字符集；运行结束提示该技能下历史运行目录数量与清理方式。

## 非目标

- **不**放宽 R13 阶段 0 DoD 门禁（主观未裁定仍须阻断宣告完成、仍为非 0 退出码）。
- **不**自动删除任何历史结果目录（跨平台删除风险；按项目删除纪律走废纸篓，由使用者决定）。
- **不**改变 `subjective.json` 的填写职责（仍由 AI 评测执行者承担）。
- **不**修改 `assets/report.template.md` 的字段标注（模版是唯一真相源，改标注须同步 schema —— 本变更改为在 merge 层处理以规避）。

## 依据

- 规则层：`AGENTS_RULES.md` 一致性核对手段表（改质量报告流水线文件后跑 `validate_quality_report.py --objective` 退出码 0）；模版 `assets/report.template.md` 为唯一真相源，字段标注由 `schema_from_template.py` 单向派生。
- 实测证据：`quality/results/report_data.json` 中 `deps_tools/deps_skills/deps_commands` 均为 `{"rows": [], "skipped": True}`；`render_report.py:33` 定义「未检查 = 未产出数据（需 LLM 裁定而未裁定）」。
- 载体：治理台账 `.project/TASKLOG.md` G23 / G24 为同期发现，本变更不重复承载。
