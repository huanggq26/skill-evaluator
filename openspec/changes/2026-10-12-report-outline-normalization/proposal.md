# 变更提案：三份报告的提纲层级与措辞归一

## 背景（Why）

2026-10-12 aihot 全链路实测后复核报告体例，发现三处结构/措辞问题，都会影响读者定位与结论可信度。

### 问题 1：`stage0_preflight.md` 的「支撑文件评估」没有定义输出位置

`references/stage0_preflight.md:373` 定义了**支撑文件评估的做法**（发现清单、按类型适配四子类、引用完整性双向校验），
但**没有指明评估结果落到报告的哪一节**。实证后果：

- 报告里没有「支撑文件评估」这一节，其结论被**打散**到「格式检查 / 内容验证 / 内容冗余 / 生态适配」各节
- 「随包资源完整性」孤零零挂在 H3（模板 133 行），与它本该归属的支撑文件评估**分离**
- 读者无法回答"这个技能的支撑文件整体评估结论是什么"

### 问题 2：质量评测报告的提纲层级不对等

模板当前把 `## 技能摘要`（H2）作为父级，把下列全部设为 H3：

```
## 技能摘要            ← H2（父）
### 格式检查           ← H3
### 对外依赖           ← H3
### 内容验证           ← H3
### 生态适配           ← H3
### 外部依赖可用性      ← H3
### 随包资源完整性      ← H3
### 关键问题汇总        ← H3
```

`技能摘要` 只是「字数统计 / 目录结构 / 多模态 / 功能表 / 产出物清单」这一组客观描述，
与"检查类"章节是**并列关系**，不是父子关系。现状会给读者错误暗示：以为后面几节都是摘要的附属。

### 问题 3：问题报告的体例不一致

| 现象 | 实证 |
|---|---|
| 手工编号不统一 | 「一、已确认安全问题」「三、功能任务问题」「三点五、告知性链接不可达」「四、质量评估」混用 |
| 层次跳跃 | 「四、质量评估」直接进入「严重（影响正常加载运行）」，缺中间层 |
| 措辞不可判定 | 摘要「已确认问题 · 按严重度」——读者无法判断什么叫"已确认"，其余问题是否"未确认" |

> 注：`assets/problem_report.template.md` 的标题**改动不生效**（v4 实证，见 `assemble_findings.py:316` 注释），
> 故问题报告的标题须改 `assemble_findings.py` 代码，模板不动。

## 目标契约

1. **质量评测报告**：`技能摘要 / 格式检查 / 对外依赖 / 内容验证 / 生态适配 / 支撑文件评估 / 外部依赖可用性 / 关键问题汇总`
   全部为**同级 H2**；其下子项为 H3。
2. **支撑文件评估**：新增同级 H2 节；把「随包资源完整性」并入其下作 H3；
   `stage0_preflight.md` 的支撑文件评估节补上**输出位置**定义（指向模板该节）。
3. **问题报告**：去除全部手工编号（交由 Markdown 渲染自动编号）；补齐层次跳跃；
   「已确认问题」改为**可判定**措辞，并给出"已确认"的判定口径。

## 非目标

- 不改任何维度的数据来源与评分口径（纯呈现层归一）。
- 不改 `problem_report.template.md`（其标题不生效，改了无效）。
- 不动 `schema_from_template.py` 的派生规则，只在其后跑比对确认无漂移。

## 依据

- 规则层：`assets/report.template.md` 为**唯一真相源**，字段标注由 `scripts/schema_from_template.py` 单向派生 →
  改模板后**必须**跑比对；改质量报告流水线文件后须跑 `validate_quality_report.py --objective` 退出码 0。
- `assemble_findings.py:316` 注释：`problem_report.template.md` 标题改动不生效（v4 实证）。
