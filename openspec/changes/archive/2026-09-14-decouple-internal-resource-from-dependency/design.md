## Context

见 `proposal.md - Why`。此处只补充方案所需的技术现状：

1. **数据层现状**：依赖探测把随包探测结果并入可用性维度列表，与外部依赖一并通过/失败计数、一并参与评分计算与否决判定。
2. **展示层现状**：基准报告已按外部维度单独统计通过/失败（此前为避免"外部 6 项：通过 10"打的补丁），并已写明"可用性评分只统计外部运行时依赖"。**即展示层已正确，评分层未兑现。**
3. **质量报告已消费探测产物**：客观数据层已读取依赖探测产物，并把维度中 **status == fail** 的行映射进质量报告的「外部依赖可用性」小节（级别：契约缺陷→严重，其余→警告）。
   - **推论（关键）**：随包项当前混在维度中，因此**随包不可读现在确实会出现在质量报告里**。若本次只把它移出维度而不补映射，**该提示将丢失**——与"评测要发现问题并提示改进"相悖。故必须配套新增映射与呈现（见决策 7）。
4. **管线时序可行**：依赖提取与探测（0B/1、0B/2）**早于**质量报告渲染（0/c），故质量报告可以消费随包探测结果，无需调整管线顺序。
5. **不可达分支**：随包资源的采集只登记实际存在的文件（遍历目录 + 存在性判断），因此"随包缺失"状态永不产生——其在否决判定中的位置是死代码。
6. **历史任务**：本变更承接治理区任务记录中的 P1（2026-08-31 登记），其「继承策略」6 条须在实施时逐条映射，禁止重写丢失。
7. **实施期发现的佐证**：规则层「可用性标记落地断言」段早有规定——`dependency_expected` 由 `external_deps` 非空**唯一判定**。而改前的 `expected = bool(deps + internal)` **违反**了该规定。故本次不是改变语义，而是**让实现回到规则层既有规定**，同时补上迁移后仍须「发现问题就提示」的呈现责任。

## Goals / Non-Goals

**Goals:**

- 让可用性评分的实现兑现报告文案已有口径（只统计外部运行时依赖）。
- 随包探测结果移出评分与否决后，**仍在质量报告中呈现并提示改进**（发现问题必须警告）。
- 清理不产生信号的"随包缺失"否决分支。
- 保证"无外部依赖"技能的应测判定不退化。

**Non-Goals:**

- 不改阶段 0 静态评测的**既有检查项**（资源链接有效、外联格式可解析等保持原样）；本次仅**新增**随包完整性小节。
- 不改外部依赖的探测逻辑（可达性、认证、配额判定）。
- 不改总分权重与裁决分档。
- 不在基准报告中呈现随包明细（已声明属阶段 0，避免重复）。

## Decisions

**决策 1：保留随包探测，移出评分与否决，结果必须在质量报告中呈现（D 方案）**

- 理由：① 移出评分，是因为"包里带没带全"与"运行时依赖是否可用"性质不同；② **保留并呈现**，是因为评测的意义在于发现问题并提示改进——若发现随包缺失或不可读却不提示，等于放弃该项评测的价值。
- 消费者：**质量报告「随包资源完整性」小节**（见决策 7）；基准报告不呈现。
- 备选：完全删除（丢失"存在但不可读"信号）；仅留数据不呈现（无消费者，等于没做）——均不采纳。

**决策 2：随包结果输出到独立字段，既有计数字段保留**

- 理由：与可用性维度彻底解耦，下游按独立字段消费；保留既有计数可避免破坏已依赖该字段的读取方，属非破坏性变更。
- 取舍：短期存在"计数仍在、但不参与评分"的过渡状态，需在字段用途上写明，避免读者误以为计数仍影响评分。

**决策 3：删除不可达的"随包缺失"否决分支**

- 理由：该状态永不产生，保留会误导读者以为存在这条否决路径。
- 取舍：若未来采集改为"约定应存在的路径清单"（而非遍历实际文件），该状态将重新可达——此时应重建分支并同步本规范，**不在本次预留空壳**。
- 注意：**分支删除 ≠ 问题不呈现**。质量报告的呈现依赖独立字段中的状态，不依赖该否决分支（见决策 7 的场景"随包文件缺失"）。

**决策 4：应测判定改为以"是否声明外部依赖"为准**

- 理由：随包资源不再是"应有可用性探测"的依据；无外部依赖即不适用。这与既有方向（无外部依赖时安全探测 N/A）一致。
- 风险：须回归确认"无外部依赖"被判为**不适用**而非**缺失**，不触发 REJECT。

**决策 5：报告文案保持不变（基准报告）**

- 理由：基准报告文案的口径本就正确，本次改实现而非改文案，避免"为了让代码通过而放宽文案"。
- 例外：仅新增质量报告的随包完整性小节（决策 7），属新增呈现，非改既有文案。

**决策 6：接受基准报告一处条件文案自然消失，不另补**

- 事实：基准报告的「口径说明」中有一句**条件输出**——"另有 N 项随包文件检查属阶段 0 静态评测范畴，仅作完整性提示，不计入本可用性评分"，仅当可用性维度中仍含随包项时才输出。
- 变化：随包项移出该维度后，该句不再输出。
- 理由：该句的作用是解释"为何维度里存在随包项却不参与评分"；解耦后维度中已无随包项，**解释的前提消失**。同一报告另一处「随包文件完整性不在此重复呈现」为**静态输出**，仍会保留，读者获得的信息不减少。
- 约束：实施时须确认该句消失**且**静态说明仍在；**并且**质量报告新小节能呈现随包问题——三者合并验证，确保"提示不丢、只是换了地方"。

**决策 7：随包问题的呈现位置、级别与划界**

- **位置**：质量报告中与「外部依赖可用性」**并列新增**「随包资源完整性」小节，位于「关键问题汇总」之前。
  - 理由：两者相邻而分离，正对应本次"外部归外部、随包归随包"的目标；且落在问题发现区，符合"评测要发现并警告"。
- **数据来源**：随包探测的**独立字段**（不再取自可用性维度）。
- **级别**：缺失 = **严重**（运行期行为残缺）；不可读 = **警告**（多为编码或权限问题）。两者**均不否决上架**，改进建议中须明确写出"不否决上架"。
- **空值**：无问题时该小节写"**无**"（模板硬规则），不得输出空表。
- **与「对外依赖」的划界**（防新增重复检查）：「对外依赖」= 外部服务候选的静态扫描 + AI 复核；「随包资源完整性」= 技能包内本地文件的存在性与可读性，由**机器探测**。二者对象不同，不重叠。
- **不落基准报告**：基准报告已声明"随包完整性不在此重复呈现"，保持不呈现，避免同一信息两处出现。

## Risks / Trade-offs

| 风险 | 影响 | 对策 |
|------|------|------|
| 历史报告中"随包不可读拉低评分"的案例回升 | 数值变化，易被误读为回归 | 属**预期修正**；在归档说明中写明，并在回归时核对差异是否仅来自随包项 |
| 应测判定语义变化（随包不再支撑 expected） | 无外部依赖技能可能被误判 | 回归必须包含至少 1 个无外部依赖技能实例 |
| 探测产出结构变化 | 严格校验可能拒绝新增字段 | 新增字段、保留既有字段；同步校验脚本并跑通 |
| 死分支删除后留下悬空引用 | 文案映射表、类别说明可能残留 | 删除后全局检索相关词，确认无悬空引用 |
| **改质量报告模板触发 schema 与校验联动** | 模板是报告格式的唯一真相源；漏同步则校验不过或报告缺字段 | 改模板后重跑 schema 派生与报告校验；同步字段归属锚点与一致性核对（规则层硬约束） |
| **新小节长期为空**（缺失分支不可达，仅不可读会触发） | 报告出现空表或读者误判为"没检查" | 遵守"空小节写无"硬规则；回归覆盖"有不可读"与"全正常"两种用例 |
| 与既有「对外依赖」重复 | 同一问题两处呈现，形成新的冗余 | 按决策 7 的划界执行；回归时核对两节内容不重叠 |

## Open Questions

- **独立字段的确切命名**：实施时按现有产出的命名约定确定（如沿用既有前缀），不改变本方案的语义；不阻塞任务拆分。
- **随包计数是否长期保留**：本次保留（非破坏性）。若后续确认无下游消费，可在独立变更中移除，不在本次处理。
