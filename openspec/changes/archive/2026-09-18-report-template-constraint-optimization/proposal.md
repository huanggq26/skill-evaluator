## Why

阶段 0 质量评测报告存在**定义与生成逻辑分离**：报告格式由 `assets/report.template.md` 派生（定义只在一处），但「填什么、按什么标准判、判为哪一级」的规则不在模板里，而散落在规则文档与多份脚本中。

实测证据：

| 现象 | 实测 |
|---|---|
| 模板正文的 `columns` 正式声明**不生效** | 改为 4 列后派生结果仍为 3 列——生效点被顶部注释块内的示例抢占 |
| 级别是文本而非字段 | 把「严重」改为「致命」后 `_severity_of` 返回空串，**严重项静默丢失**（既不汇总也不标红） |
| 空槽位一律渲染为「无」 | 28 个槽位中 18–19 个为空（64%–68%），「已检查无问题」与「根本没结论」呈现完全一致，读者无法分辨 |
| 模板槽位与规则条目无绑定 | 模板用英文 ID、规则文档用中文小节名，对应关系无处校验 |

## 任务类别判定

- 判据：是否改变对外可观察行为 → **是**（改变报告列结构、级别呈现、空槽位表述）
- 分流：**行为变更**，任务态由本变更承载，不登记 TASKLOG（依 `openspec/config.yaml` 无双写纪律第 5 条）

## 历史错误（ERR 编号）

无。（实施期间发现新问题须即时写入错误档案）

## What Changes

| # | 变更 | 优先级 |
|---|---|---|
| R1 | 级别结构化：rows 增 `level` 字段（`Level` 枚举：`SEVERE` / `WARNING` / `NOTICE`），汇总与着色读该字段，不再从「原因」文本反推 | **P0** |
| R2 | 模板 `columns` 声明唯一化：派生器先剥离注释块再取声明；顶部示例显式化（R9） | **P0** |
| R9 | 模板顶部注释块内的示例标注改为不会被正则误匹配的形式，或加显式 skip 标记 | P3 |
| R10 | 空槽位语义分离：已检查无问题 → 「无」；未产出数据 → **「未检查」**。三条配套：不得进关键问题汇总、只能渲染层呈现（禁止落成数据行）、下游 skill-doctor 遇之跳过 | P1 |
| R4 | 槽位↔规则绑定：模板标注增 `rule:`（值为规则文档内小节名），门禁校验命中 | P1 |
