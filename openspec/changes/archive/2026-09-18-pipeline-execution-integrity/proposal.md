## Why

两处流水线行为缺陷，共同导致「流程没走完却表现为已完成」：

- **R13**：阶段 0 完成时点**没有判定标准**。流水线跑完即打印「✅ 开始阶段测评完成」并给出报告绝对路径；主观维度未裁定时仅在 stderr 打一行小字，**不阻断、不改完成播报、`full/resume` 模式还会自动接续阶段 1–4**。而 `SKILL.md` 早有纪律「前一阶段 DoD 满足才进下一阶段」「DoD 验证完成后再发阶段完成播报」「不静默跳过门禁」——纪律存在但未落地。
- **R11**：工作区清空为可选开关（`--reset`），默认只覆盖同名文件、不清目录，导致上次遗留且本次不再产生的陈旧文件滞留。

## 任务类别判定

- 判据：是否改变对外可观察行为 → **是**（改变是否宣告完成、是否推进下一阶段、是否删除目录）
- 分流：**行为变更**，任务态由本变更承载，不登记 TASKLOG

## 历史错误（ERR 编号）

无。

## What Changes

| # | 变更 | 优先级 |
|---|---|---|
| R13 | 阶段 0 的 DoD 增列「主观维度已裁定（未产出结论槽位数 = 0）」；未满足时：① 不打印「✅ …完成」播报；② 不给出「报告已生成 / 可查看」提示；③ 驱动 LLM 回到填充步骤补做；④ `full/resume` 不得自动接续阶段 1–4 | P1 |
| R11 | 开始评测**默认**先清空本次被测技能的工作区子目录（仅该子目录，其他技能结果保留） | P2（**风险最高**） |

## Scope（范围）

- `scripts/run_eval_pipeline.sh`（完成播报、推进逻辑、工作区清空）
- `SKILL.md`（阶段完成播报与推进规则，与既有纪律对齐）

## Non-goals（非目标）

- 不改各阶段内部的评测逻辑与判级规则
- 不改报告模板与章节结构（另立变更）
- 不改结果目录的顶层结构（仍按技能分子目录）

## 风险控制（重点）

| 项 | 风险 | 处置 |
|---|---|---|
| R11 删除用户数据 | **最高**：默认清空会删除既有结果目录 | ① 只删本次被测技能的子目录，**绝不删** `RESULTS_ROOT` 整体；② 播报明确告知删除范围；③ 作为**独立可回滚步骤**实施，与 R13 分步 |
| R13 改变推进语义 | 高：`full/resume` 不再自动接续，可能改变既有使用体验 | 先统计未裁定发生的频率再定启用范围；未完成时须明确告知「未完成，需补做」而非静默 |
| Windows 环境 | `rm -rf` 依赖 bash（Git Bash / WSL）；改为默认后该依赖被放大 | 实施前确认目标环境；必要时改用跨平台删除实现（上个版本实测环境即 Windows） |
