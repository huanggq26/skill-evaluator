# 逐标签可判定性分级表

> 产出时间：2026-10-12　任务：**#1-h-a**
> 用途：决定**哪些标签留在打标集**（需要真值、要算召回率/精确率），哪些**移出打标集**（改为只记 `evidence_level`，不再算度量）。
> 本表是 **#3（标签集拆分与信号收窄）的实施范围依据**——只有本表判定为 A 级的标签才允许继续拥有真值与门禁指标。
> 依据文件：`kappa_round2_summary.json`（第二轮留出 5 个）、第三轮无偏 10 个（本表实算）、`annotation_guide.md` v4。

---

## 1. 分级定义

| 级别 | 含义 | 处置 |
|---|---|---|
| **A** | 判据可写成 **E1（代码事实）/ E2（声明事实）** 的是非判断，两个标注者照抄判据应得到同一答案 | **留在打标集**，需要真值，可设召回率门禁 |
| **B** | 判据依赖**语义推断**（"这算不算…"），无法写成事实判定 | **移出打标集**，不再触发标签；相关信号只写入 `evidence_level`（E3/E4），报告中标注"未经真值验证" |
| **C** | 判据可机械判定，但在真实分布中**近恒真或近恒假**（无法构造阴阳样本） | 与 `exec_code` 合并或**剔除**；若保留必须**定向构造样本**才谈召回率 |

### 2.2 第二轮留出样本（5 个技能 / 55 判定对，总体 κ = 0.5565）

`exec_code` / `external_dep` / `net_egress` κ = 1.0；`cred_access` −0.25、`state_persist` −0.154、`fs_access` 0.0、`prompt_intent` 0.0、`tool_calls` 0.0；`agent_comms` / `system_instruction` 双方全 no。

### 2.3 从数据读出的三条判据

1. **4 个 κ=1.0 是假的**——全 yes / 全 no 使 κ 分子分母同向放大，κ 恒为 1，**不含任何判别信息**（#1-f 已记录）。
2. **有判别信息的 7 个标签最高只有 0.444**，且 `fs_access` 为负 → 在**语义型判据**下，本真值不足以支撑任何标签的召回率/精确率度量。
3. **B 面 374 判定 `unsure`=0 且条条带证据位置** → 分歧出在**标签定义**，不是标注态度或规程文字 → 再修订规程无效，必须改判据形态（语义推断 → 事实判定）。

## 3. 分级结果（11 个标签）

| # | 标签 | 级别 | 判据能否写成 E1/E2 | 处置 |
|---|---|---|---|---|
| 1 | `exec_code` | **A** | 能：`scripts/` 内出现 `subprocess` / `os.system` / `exec` / `eval` / `importlib` / `os.popen` 等执行类调用 | 保留；**判据收紧为 E1/E2** |
| 2 | `external_dep` | **A** | 能：存在 `requirements.txt` / `package.json` / `pyproject.toml`，或显式 `pip install` / `npm install` / MCP server 声明 | 保留；**判据需枚举来源清单**（消歧最大项，κ 最高说明最可判） |
| 3 | `fs_access` | **A** | 能：代码内出现文件读写 API（`open(` / `Path().read_text` / `write_text` / `os.remove` / `shutil`） | 保留；**判据收紧**：工具名（`read_file` 等）不算，否则与 `tool_calls` 恒重叠 |
| 4 | `net_egress` | **A** | 能：出现 HTTP 客户端调用（`requests.` / `httpx` / `urllib` / `fetch(`）或 `curl` / `wget` | 保留；**边界**："云端服务"仅描述不算，那是 `external_dep` |
| 5 | `cred_access` | **A** | 能：出现 `os.environ` / `getenv` / `~/.ssh` / `~/.aws` / `.env` / 凭证类词形 | 保留；**词形字典最大受益项**（现仅 `token`/`令牌`，缺 `credential`/`secret`/`api_key`/`AK/SK`） |
| 6 | `state_persist` | **A** | 能：出现**写操作到非临时路径**（写 `*.json` 状态文件 / SQLite / memory 目录） | 保留；**必须剔除恒真信号** `\.md` / `\.json`（现口径下 10/10 技能都命中） |
| 7 | `agent_comms` | **A**（样本不足） | 能：出现 `send_message` / `spawn … agent` / mailbox / team 编排 | 保留；**真值需定向构造**——自然分布下本池 0 阳性 |
| 8 | `system_instruction` | **A**（样本不足） | 能：出现对系统提示/安全策略的**写入或覆盖**语句 | 保留；**真值需定向构造**——295 技能检索仅 2 候选，且均为"产出提示词给人用"，本池 0 真阳性 |
| 9 | `user_content` | **B** | 不能："是否加工用户输入"近乎恒真（第三轮 A 判 8/10） | **移出打标集**；信号降级记入 `evidence_level`（E3） |
| 10 | `prompt_intent` | **B** | 不能："是否存在可被输入改写的意图"需推断作者意图；A/B 双向分歧（第二轮 −0.15） | **移出打标集**；信号降级记入 `evidence_level`（E3/E4） |
| 11 | `tool_calls` | **C** | 能，但**恒真**：任何技能都调用工具，与 `exec_code` 恒重叠 | **剔除**（并入 `exec_code` 的宽口径信号，或仅作展示字段，不设门禁） |

**汇总：A 级 8 个（其中 4 个须改判据：`exec_code` / `fs_access` / `state_persist` / `net_egress`；2 个须定向造样本：`agent_comms` / `system_instruction`）、B 级 2 个、C 级 1 个。**

## 4. E1–E2 打标约束（#1-h-b 的重标口径）

> 这条约束是本表能落地的**根**：不改判据形态，重标只会重复第三轮的 κ=0.60。

- **打标只认 E1 / E2**：E1 = 代码事实（可 grep 到行号）、E2 = 声明事实（`requirements.txt`、frontmatter、显式依赖声明）。
- **E3 / E4 不触发标签**：SKILL.md 的指令文本、强隐含 → 只写入 `evidence_level`，**不置 yes**。
  - 例：`SKILL.md:L127 运行 bash scripts/get-token.sh` 是 **E3**，按新口径 `exec_code` 判 **no**（指令说了要做，但本体无执行代码）；`cred_access` 仍可因 `get-token.sh` 内读取凭证而判 yes（E1）。
- **证据位置是强制项**：每个 yes 必须带 `文件:行号` + 等级，无位置的判定作废重标。
- **被移出打标集的标签不再需要真值**（不再触发标签即无召回率可言）→ **重标范围由 11 列降为 8 列，工作量约减 27%**（B/C 级 3 个标签对应的真值列作废）。

## 5. 样本配额（解决"假一致"，硬要求）

第三轮 10 个样本中出现 4 个恒值标签，根因是 **#1-c 要求的"每标签阳性 ≥3 且阴性 ≥3"从未写进抽样脚本**。重标前必须先补配额：

| 要求 | 数值 |
|---|---|
| 每个 A 级标签 | 阳性 ≥ 3 **且** 阴性 ≥ 3（按代理信号预测后核验） |
| `exec_code` 阴性从哪来 | 定向补入**纯文档型技能**（无 `scripts/`、SKILL.md 内无执行指令） |
| `agent_comms` / `system_instruction` 阳性从哪来 | **定向构造样本**（自然分布 0 阳性，靠随机抽样永远凑不出） |
| 判定对总数 | ≥ 110（单个分歧引起 ≈0.02 κ 波动，样本量不足以下结论） |

配额未满足前，**任何 κ 数字都不可作为验收依据**。

---

## 6. 对 #3 的范围约束

1. **只有 A 级标签允许进入 `#3` 的信号收窄工作**，B 级标签不做信号收窄（因为不设门禁，收窄无收益）。
2. `state_persist` 的 `\.md` / `\.json`、`tool_calls` 的 `\bsearch\b` 等**恒真信号必须剔除**——这是 #3 验收项的硬要求，与本表一致。
3. **#3 完成后才允许接入 U10 运行时观察**补召回：静态层受 E1–E2 约束而漏掉的，由运行时观测（actual syscall / 实际请求）补回，二者互补而非互相放宽。
