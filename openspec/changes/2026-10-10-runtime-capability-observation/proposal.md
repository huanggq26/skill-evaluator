# runtime-capability-observation

## Why

静态打标存在**原理性的召回上限**：攻击面标签由扫描 `SKILL.md` 与 `scripts/` 得出，只能回答"有没有这类调用/声明"，无法覆盖运行时才出现的行为。

**实测一：改写测试（能力不变、表述改变即丢失）**（2026-10-10）

- 中文能力描述改英文 → 丢失 `prompt_intent`、`user_content`
- 命令执行改等价 API（`subprocess` → `os.popen`）→ 丢失 `exec_code`
- 联网技能 `aihot` 因词形未覆盖而漏判出网面

**实测二：可运行性不是默认成立**。`exec_functional_tasks.py` 需端点可达，无端点时改读包内文件；v16 对抗请求**大量返回 405**（请求未被服务端接收）——相当比例的探测**并未真正触达被测逻辑**。产物已有 `probe_effective` 字段标注。

**实测三：运行时动态生成的行为不可静态观测**。LLM 在运行时推理生成的命令与调用不在任何静态文本中，静态手段在原理上无法覆盖。

**结论**：需要把**运行时实际观测到的能力**作为打标证据补入，与静态结论合并（OR）。

**完整论证**：`~/Downloads/运行时能力观测项目策略_2026-10-10.md`

### 与 skill-doctor 的关系（已核查，结论为"不合并、不复用"）

| 项 | 结论 |

| 定位 | 不重复：doctor = 改进诊断（一次性、拔桩）；本项目 = 评测（常驻、可复算） |

| 是否复用 | **不复用**：评测证据不能建立在 LLM 上报之上（漏报不可检测），与本方案"防漏检"目标冲突 |
| 是否合并 | **不合并**：doctor 明确"不互相改造""不评测"，且硬拒绝对 evaluator 插桩（退出码 2） |
| 可借鉴 | 其脚手架设计（可逆 marker、插桩前备份、拔桩纯净性校验） |

### 插桩互斥（用户已确认策略）

**实测**：向被测技能 `scripts/` 注入 tracer 脚本后，静态打标由 `secret_memory`(2) 变为 `exec_code`(6)、`fs_net_cred`(5)、`secret_memory`(12)——**新增 2 个标签、证据 +19 行，打标完全失真**。故插桩**并非"不影响静态评测"**，影响与否取决于注入物是否落在扫描面内（`SKILL.md` + `scripts/` 全递归）。

守卫按**影响范围**分级，仅在影响范围内阻断（详见 tasks #1）。

## 任务类别判定

- 判据：是否改变对外可观察行为 → **是**（改变执行环境与证据结构，产物含新字段与新来源标记）
- 分流：**行为变更** → 由规范区变更承载任务态，不登记 TASKLOG（避免双写）

## What Changes

**本次仅立"阶段一"**（按确认的立项顺序，阶段二、三待阶段一收益评估后再定）：

1. **可运行性前置**：增加 `runnable` 判定（端点可达 / 有可执行的包内流程）；不可运行时退化为静态并标注 `runtime_unavailable`，**不得以"未观测"冒充"能力不存在"**。
2. **插桩检测守卫（分级，仅在影响范围内阻断）**：
   - **L1 阻断**：扫描面内出现插桩特征（`runtime-probe` marker、`runtime_tracer.py`、frontmatter `runtime-probe:note`）→ **拒绝评测，退出码 1**（沿用既有守卫约定）
   - **L1 输出四要素（缺一不可）**：① 检测位置（`文件:行`）；② 判定依据（命中的特征名）；③ 移除指引（先拔桩，或手工删除注入块与脚本）；④ 复检方式
   - **不提供绕过开关**：不设 `--force` / `--allow-instrumented`，与 doctor 硬拒绝对 evaluator 插桩（退出码 2）对等
   - **L2 告警**：技能根目录存在 `.trace/` → 允许评测，产物标记 `purity: instrumented_residue`
   - ~~L3 打标排除~~：**已拆出**至独立变更 `2026-10-10-surface-tag-scan-exclusion`（与运行时无关且零回归，独立落地）
3. **RT-1 网络代理**：起本地记录代理，执行时设置代理环境变量，记录出网的域名 / 方法 / 路径。
   - 前提已实测：`urllib` 遵守代理环境变量（设置 `http_proxy=127.0.0.1:9` 后报 `Connection refused`），**无需改被测代码**。
4. **RT-3 Canary 凭证**：预置**无害占位**凭证到环境变量与临时 HOME 的常见路径，检测是否被读取或外带（值出现在外发请求中即标记 `cred_exfil`）。
5. **RT-0 产物反推 + 证据回写**：解析已有产物中的端点与写入路径；观测事件按统一结构回写，带 `source` 标记（`static` / `runtime` / `default`）。
6. **顺序约定**：先评测（纯净态）→ 后插桩诊断；插桩后须拔桩并通过 L1 复检才能再次评测。

**本次不做**：RT-2（临时目录 + 文件树对比）、RT-4（系统调用观测）、RT-5（工具网关埋点）——待阶段一收益评估后决定。
